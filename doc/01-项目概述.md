# 01 · 项目概述

> 最后更新：2026-11-04

## 一、项目背景

政府采购、工程建设、土地与产权等公共资源交易公告分散在多个法定平台：中国政府采购网（ccgp）、全国公共资源交易平台（ggzy）、各省公共资源交易/招标投标平台。公告格式不统一、字段缺失普遍、跨平台同一项目难以归并，用户需要反复切换站点、人工判断项目阶段。

本项目将这些**公开公告**采集、清洗、归一为统一的「项目 → 招标项目 → 标段 → 公告」四层模型，提供门户检索、项目视角浏览与本企业投标台账，并为后续的企业画像、订阅推送、AI 检索预留扩展点。

## 二、项目定位

| 维度 | 定位 |
|---|---|
| 数据来源 | 只采政府法定公开平台的公开公告，不采商业聚合平台、不采非公开渠道 |
| 数据加工 | 采集即为结构化：正文片段 + 国标字段 + 项目归并，不存整页 HTML 原始站点 |
| 产品能力 | 信息聚合 + 检索 + 项目视角 + 本企业投标台账 |
| 非目标 | 不做投标预测、不做「找关系」撮合、不做附件二次分发、不绕过源站访问控制 |
| 部署形态 | 单体多模块 Spring Boot + 三个前端（管理端 / 用户端 / 移动端） |

## 三、系统范围

### 3.1 已实现（P0 终态）

- 多源采集：`ccgp`（22 频道）、`ggzy`（10 频道）；`ztb_gz` 保留适配器但源站停用。
- 四层标讯模型：`project` / `tender_project` / `tender_lot` / `notice`。
- 企业主体：`enterprise` / `enterprise_role` / `enterprise_contact` / `enterprise_alias`，公告与企业通过 `notice_enterprise` 关联。
- 基础数据：`base_area`（省级 34 + 演示城市 17）、`base_code`（公告类型 / 采购方式 / 角色等编码集）、`base_field_mapping`。
- 采集治理：`crawler_channel`、`crawler_fetch_log`、`crawl_raw`、`crawl_parse_rule`、`crawl_merge_log`、`notice_quality`。
- 门户接口：公告分页/详情/首页统计/省市/行业，项目分页/详情。
- 用户端：首页、公告列表、公告详情、我的投标、登录/注册；管理端：采集中心、系统管理、基础设施、若干毕设占位页。
- 投标台账：`bid_project` 五状态机。
- 会员认证：账号密码 + 滑块验证码，OAuth2 Bearer Token（MEMBER 类型）。

## 五、术语表

| 术语 | 含义 |
|---|---|
| 标讯 / 公告 | 源站发布的一条信息记录，落在 `notice` |
| 项目（project） | 跨公告聚合的业务对象，按 `project_key` 归并 |
| 招标项目（tender_project） | 一个项目下的一次招标活动，可包含多个标段 |
| 标段（tender_lot） | 招标项目下的包/标段；无标段信息时生成 `lot_no='DEFAULT'` |
| 企业主体（enterprise） | 招标人、代理机构、中标人等实体的主档 |
| 源站（site） | 被采集的公开平台，配置在 `crawler_site` |
| 频道（channel） | 源站下的栏目/类别，配置在 `crawler_channel` |
| P0 | 数据模型重构的第一阶段：基础数据、企业主体、四层标讯、采集治理 |
| 规则抽取 | crawler 用关键词/词典从标题与正文推导的字段（如 `industry`），不是权威标签 |
| 原始层 | `crawl_raw` 保存的源站页面快照，只增不改，可重放解析 |
