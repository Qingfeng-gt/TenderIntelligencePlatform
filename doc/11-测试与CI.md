# 11 · 测试与 CI

> 最后更新：2026-11-04

## 一、测试策略

| 层级 | 范围 | 工具 | 目标 |
|---|---|---|---|
| 单元测试 | 解析器、状态机、工具类 | JUnit 5 + AssertJ | 纯逻辑正确 |
| 服务测试 | Service 规则、事务 | JUnit 5 + Mockito | 业务规则与异常 |
| 集成测试 | 接口 + 数据库 | Spring Boot Test + H2 / MySQL | 关键链路 |
| 前端检查 | 类型、构建 | `vue-tsc` / `vite build` | 可编译、类型正确 |
| 冒烟测试 | 启动、登录、公告查询、采集触发 | 手工 / curl | 端到端可用 |

> 当前项目以单元测试 + 手工冒烟为主；集成测试按需补充。

## 二、后端测试

### 2.1 命令

```bash
cd backend

# 编译
mvn -DskipTests compile

# 全量测试
mvn test

# 指定模块
mvn -pl tender-module-crawler -am test

# 指定测试类
mvn -pl tender-module-crawler -am \
  -Dtest=GgzyNoticeParserTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

### 2.2 现有测试

| 测试 | 覆盖 |
|---|---|
| `GgzyNoticeParserTest` | ggzy 类型判定、省市归一、截止/开标、联系人、附件 |
| `CcgpAttachmentParserTest` | ccgp 附件解析 |
| 框架自带测试 | system / infra |

### 2.3 测试约定

- 解析器测试使用固定 HTML/JSON 样本，不依赖外网。
- 状态机测试覆盖所有合法/非法迁移。
- Service 测试用 Mockito 隔离 Mapper。
- 不把生产数据/密钥写入测试。
- 新增源站必须补解析器测试。

## 三、前端检查

```bash
cd user-web && pnpm install && pnpm build
cd admin-web && pnpm install && pnpm ts:check && pnpm build:prod
cd tender-app && pnpm install && pnpm build:h5
```

要求：

- TypeScript 无错误。
- 构建产物路径与 CI 一致（`dist` / `dist-prod` / `dist/build/h5`）。
- 无未使用的变量/导入（按 ESLint 规则）。

## 四、CI 流水线

文件：`.github/workflows/ci.yml`

### 4.1 触发条件

- push 到 `master`
- PR 到 `master`
- 手动 `workflow_dispatch`

### 4.2 后端 Job

```yaml
runs-on: ubuntu-latest
steps:
  - checkout
  - setup-java 17 (temurin, maven cache)
  - mvn -B -T 1C clean package -DskipTests
  - upload backend/tender-server/target/*.jar
```

> CI 当前跳过测试（`-DskipTests`），以构建通过为准；本地提交前应跑相关测试。

### 4.3 前端 Job（矩阵）

| app | 构建脚本 | 产物目录 |
|---|---|---|
| `admin-web` | `build:prod` | `dist-prod` |
| `user-web` | `build` | `dist` |
| `tender-app` | `build:h5` | `dist/build/h5` |

环境：

- Node 24
- pnpm 12
- `pnpm install --frozen-lockfile`
- 上传各端产物

### 4.4 并发

- `concurrency.group = ci-${{ github.ref }}`
- `cancel-in-progress: true`：连推多次只保留最新一次。

## 五、质量门禁

| 门禁 | 要求 |
|---|---|
| 编译 | 后端 `mvn package` 通过 |
| 类型 | 前端 `vue-tsc` 通过 |
| 构建 | 三端产物生成 |
| 测试 | 改动模块相关测试通过（本地/评审） |
| 文档 | 表结构/接口变更同步更新 |
| 安全 | 无密钥/密码进入提交 |

## 六、手工冒烟清单

```bash
# 1. 后端启动
cd backend
mvn -pl tender-server -am -DskipTests package
java -jar tender-server/target/tender-server.jar --spring.profiles.active=local

# 2. 健康检查
curl http://127.0.0.1:48080/actuator/health

# 3. 公告接口
curl "http://127.0.0.1:48080/admin-api/notice/overview"
curl "http://127.0.0.1:48080/admin-api/notice/page?pageNo=1&pageSize=5"
curl "http://127.0.0.1:48080/admin-api/notice/detail?id=1"

# 4. 采集（需 ADMIN Token）
curl -X POST "http://127.0.0.1:48080/admin-api/crawler/run?siteCode=ccgp" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"

# 5. 会员登录（local 验证码关闭时）
curl -X POST "http://127.0.0.1:48080/app-api/member/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"demo123","password":"123456"}'
```

## 七、常见问题

| 问题 | 排查 |
|---|---|
| 后端启动报缺表 | 是否执行了 `backend/sql/mysql/notice.sql`（业务最终结构 + 种子） |
| 采集任务一直 RUNNING | 查看日志、`crawler_fetch_log`；超过 4 小时会被回收 |
| 前端 401 | Token 过期/类型不匹配；确认 `/admin-api` vs `/app-api` |
| 公告列表为空 | 是否执行过采集；`notice` 是否有数据 |
| 构建失败在 CI 但本地通过 | 检查 Node/pnpm 版本、产物路径、大小写 |
| Mermaid 图不显示 | 用支持 Mermaid/SVG 的查看器；或看 `doc/diagrams/*.svg` |
