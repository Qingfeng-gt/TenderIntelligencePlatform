## 三、初始化数据库

```bash
# 1) 框架基础（自动创建并使用 tender 库）
mysql -uroot -p < backend/sql/mysql/tender.sql

# 2) 业务最终结构 + 基础/站点/菜单种子（业务表为空，等待采集）
mysql -uroot -p < backend/sql/mysql/notice.sql

# 2.1) 可选：20 条演示公告 + 四层关联，用于门户联调
mysql -uroot -p < backend/sql/mysql/demo-data.sql

# 3) 仅 dev/test 需要 Quartz
mysql -uroot -p < backend/sql/mysql/quartz.sql
```

> `notice.sql` 已是 P0 终态结构，**不需要再执行 `refactor/P0__run_all.sh`**。  
> `refactor/` 仅保留作已存在库的历史迁移记录；新库不要跑增量脚本。
>
> `notice.sql` 对业务表是 DROP + CREATE：重复执行会清空业务数据并保留基础/站点/菜单种子；框架表（`system_*` / `infra_*` / `member_user`）不受影响。  
> 演示数据是独立可选的 `demo-data.sql`；正式采集前不需要执行它。

验证：

```sql
USE tender;
SELECT COUNT(*) FROM notice;
SELECT COUNT(*) FROM project;
SELECT COUNT(*) FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA='tender' AND TABLE_NAME='notice'
   AND COLUMN_NAME IN ('type','province','city','tender_person','agency','deadline','source');
-- 最后一条应为 0
```

## 七、常见开发任务

### 7.1 新增一个后端接口

1. 在对应模块 `controller/admin|app/...` 新建 Controller 或方法。
2. 入参 `ReqVO` 加 `@Schema` 与校验注解。
3. Service 实现业务；Mapper 写查询。
4. 返回 `CommonResult.success(...)`；错误用 `ErrorCodeConstants`。
5. 在 [08 接口设计规范](08-接口设计规范.md) 与 Knife4j 注解中同步。
6. 前端 `api/` 加请求函数，`types.ts` 加类型。

### 7.2 新增/修改一张业务表

1. **新库**：直接修改 `backend/sql/mysql/notice.sql` 中的建表段（当前为最终结构）。
2. **已存在库**：在 `backend/sql/mysql/refactor/` 新增 `P0-x__xxx.sql`（或后续批次），附 `*_rollback.sql`。
3. 建表遵循 [09 数据库设计规范](09-数据库设计规范.md)。
4. 新建 DO + Mapper；包名 `dal/dataobject` / `dal/mysql`。
5. Service/Controller 接入。
6. 更新 [05 数据模型与 ER 图](05-数据模型与ER图.md)。

### 7.3 新增采集源站

见 [06 数据采集设计 §9](06-数据采集设计.md#九新增源站步骤)。

### 7.4 新增管理端页面

1. `admin-web/src/views/<path>/index.vue`。
2. `system_menu` 插菜单：`path`、`component`、`component_name` 必须与文件路径一致。
3. 刷新管理端（动态路由从菜单生成）。
4. 如页面需要权限点，补 `@PreAuthorize` 与菜单按钮权限。

### 7.5 新增用户端页面

1. `user-web/src/views/XxxPage.vue`。
2. `user-web/src/router/index.ts` 加路由；需要登录加 `meta.requiresAuth`。
3. `api/` 加请求函数。

### 7.6 修改公告字段

同步链路：

```text
NoticeDTO（写）
  → NoticePortalDO（DO）
  → notice 表 DDL
  → NoticeRespVO（读）
  → NoticeViewAssembler
  → user-web/src/types.ts / 页面
  → 文档 05 / 08
```

## 九、FAQ

**Q：启动报 `Unknown database 'tender'`？**  
A：执行 `backend/sql/mysql/tender.sql`，脚本会自动建库。

**Q：启动报缺 `project` / `enterprise` 表？**  
A：执行 `backend/sql/mysql/notice.sql`，该脚本直接创建四层模型、企业主体、基础数据与采集治理表。

**Q：还需要执行 `refactor/P0__run_all.sh` 吗？**  
A：新库不需要。`notice.sql` 已是 P0 终态结构；`refactor/` 仅用于已存在旧库的历史迁移。

**Q：采集任务一直 RUNNING？**  
A：看后端日志与 `crawler_fetch_log`；超过 4 小时会被自动回收。检查源站可达性、UA、限流。

**Q：门户列表为空？**  
A：确认 `notice` 有数据；执行一轮采集；检查 `source_url` 是否唯一。

**Q：前端 401？**  
A：管理端用 ADMIN Token，用户端用 MEMBER Token；检查 `Authorization` 头与 URL 前缀。

**Q：Mermaid 图不显示？**  
A：使用支持 Mermaid 的查看器，或直接打开 `doc/diagrams/*.svg`。

**Q：`/system/user` 里为什么看不到 user-web 的会员？**  
A：`/system/user` 管理的是后台管理员 `system_users`；user-web 会员在 `member_user`，请到管理后台「会员管理」（`/member/user`）查看、启停和重置密码。

**Q：编译后启动报 `NoClassDefFoundError`，提示某个已经删除的类？**  
A：`target/classes` 里残留了旧的 `.class`。Maven 增量编译不会自动清理已删除源码对应的 class。执行：

```bash
mvn clean package -DskipTests
```

或直接删除各模块的 `target/` 后重新构建。

**Q：WSL 下 Maven 报 `Could not create local repository at /home/administrator/.m2/repository`？**  
A：`~/.m2/repository` 是指向 Windows 用户目录的符号链接，但目标不存在。常见原因是链接到了 `/mnt/c/Users/Administrator/.m2/repository`，而实际 Windows 用户是 `27585`。修复：

```bash
rm ~/.m2/repository
ln -s /mnt/c/Users/27585/.m2/repository ~/.m2/repository
```

验证：`mvn -v` 能正常显示，`mvn -DskipTests package` 应成功。

**Q：Windows 下 Maven 编译报 Lombok/JDK 错误？**  
A：使用 JDK 17；项目 Lombok 版本与 JDK 27 不兼容。可在 WSL 中用 JDK 17 构建。

## 十、IDE 建议

- IntelliJ IDEA：安装 Lombok、MapStruct 插件；开启注解处理。
- VS Code：安装 Vue - Official、ESLint、Prettier、Mermaid Preview。
