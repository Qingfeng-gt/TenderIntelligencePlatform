## 一、产品定位

### 1.1 一句话定位

**面向投标侧企业的招投标情报检索平台：用户输入关键词，即可在同一个入口检索来自政府法定公开平台的标讯，阅读原文关键字段并溯源到源站，进而登记并跟进投标。**

产品是**资源整合平台**，整合的是「信息的检索入口」，不是「信息的再分发渠道」。系统内呈现的每一条标讯都保留来源站点与源站详情 URL，用户要办事仍回到源站。

### 1.2 目标用户

| 用户类型 | 典型角色 | 核心诉求 |
|---|---|---|
| 投标企业 | 经营/商务负责人、招投标专员 | 不漏标、快速筛出可投项目、掌握截止时间 |
| 供应商 | 产品销售、渠道经理 | 从采购公告中识别采购需求与采购人 |
| 销售代表 | 大客户销售、区域销售 | 通过采购人/代理机构线索建立联系（**线索本身来自公告公开字段**） |
| 代理商 / 中间商 | 区域代理、集成商 | 关注特定地区与行业的持续标讯流 |
| 投标管理者 | 项目负责人 | 对本企业参与的投标做立项、状态跟踪与复盘 |

### 1.3 核心使用场景

```
搜关键词 → 看全网标讯 → 读关键字段并溯源 → 找商机 → 跟进投标 → 状态复盘
```

1. **搜**：在首页或标讯大厅输入关键词（如「数据中心」「污水处理」），见 [`09-数据源清单.md`](../数据/09-数据源清单.md) 中已接入源的最新公告。
2. **看**：列表按类型（招标/中标/变更/采购）与地区、行业、时间筛选。
3. **溯源**：详情页展示项目编号、预算、招标人、代理机构、联系人、投标截止、开标时间与公告正文；`source` + `sourceUrl` 可回跳源站核对。
4. **找商机**：按地区/行业/时间圈定目标池，形成本企业的机会清单（当前为人工判断，二期引入订阅）。
5. **跟进投标**：在平台内登记投标项目并维护状态，形成自用的投标台账。

### 1.4 与竞品的根本差异

| 维度 | 定位差异 |
|---|---|
| 数据来源 | 只采**政府法定公开平台**（国家级与省级公共资源交易平台、政府采购网）的公告正文页，不采商业聚合平台、不采非公开渠道 |
| 数据可信 | 每条记录保留 `source`（来源站点）与 `source_url`（源站详情 URL，唯一键去重），可逐条回源核对 |
| 数据加工 | 采集即加工：**只保留用户关注的内容**（正文富文本片段 + 12 个结构化字段），**原始 HTML 页面不入库**。不做二次创作/改写，不做数据的对外再分发 |
| 能力边界 | 只做**信息整合 + 检索**，并在此基础上做本企业内部的投标台账管理 |
| 明确排除 | 不做「提前 1-6 月独家预测项目」「避免内定项目」「找关系合作投标」这类依赖非公开情报或触及串通投标红线的能力（见 [第三章](#三能力对照表本项目的现状) 与 [第六章](#六合规与数据边界)） |
| 商业模式 | 一期不设付费墙。会员体系与套餐支付列为二期，见 [第五章](#五路线图分阶段) |

**需要诚实说明的现状差距**：对标产品的宣传口径是「全国全网实时 30 万+/天」。本项目一期只接入 2 个源（`ccgp`、`ztb_gz`），其中 `ztb_gz` 源站列表接口当前返回 0 条。所以现阶段的准确定位是：**「可扩充的多源采集架构 + 已跑通的端到端闭环」**，而不是「全网覆盖」。「全网」是二期的工程量目标，不是当前事实。

## 六、合规与数据边界

### 6.1 数据来源边界

| 边界 | 约定 | 落地情况 |
|---|---|---|
| 只采政府法定公开平台 | 国家级与省级公共资源交易平台、政府采购网 | 已接入 `ccgp`（中国政府采购网，财政部主管）、`ztb_gz`（贵州省招标投标公共服务平台） |
| 不采商业聚合平台 | 千里马、剑鱼标讯等在 [`09-数据源清单.md`](../数据/09-数据源清单.md) 中列为**竞品/参照**，非采集目标 | 已在数据源清单中标注 |
| 只抓公告正文页 | 不抓取附件文件（招标文件 PDF/Word 等） | 一期实现层面已遵守 |
| 不做知识产权数字化传播 | 不做二次创作、不做对外再分发；只保留公告正文片段，原始页面 HTML 不留存 | `notice.content` 存正文富文本**片段**（非原样页面），前端 `v-html` 渲染 |

### 6.2 溯源要求

- 每条标讯**必须**写入 `source`（来源站点名）与 `source_url`（源站详情 URL）。
- `source_url` 为**唯一键**（`notice.uk_source_url`），既作去重依据，也作溯源依据。
- 用户端详情页展示来源，用户可回源站核对原文；法律效力以政府官网公告为准。

### 6.3 采集行为约束

| 约束 | 实现 |
|---|---|
| 遵守 robots 约定 | 选型阶段已排除明确拒绝抓取的源；接入新源前需先核查其 robots |
| 频控 | 站点级 `interval_ms` 详情页间隔，**默认 3000ms**；`ztb_gz` 在列表翻页与重试之间同样休眠 |
| 串行化 | 采集提交到单线程守护线程池（线程名 `crawler-run`），避免并发打爆源站 |
| 防重入 | 站点级 RUNNING 任务守卫 + 4 小时超时任务自动回收 |
| 请求头模拟 | Cookie 预热 + `Referer` + 浏览器 UA +（`ztb_gz`）`X-Requested-With: XMLHttpRequest` |

> 说明：上述手段的定位是**降低对源站的访问压力**，属于礼貌抓取的工程实现，不是绕过访问控制。选型阶段的实测结论（哪些源因限流/人机验证/JS 渲染而不可用）见 [`09-数据源清单.md`](../数据/09-数据源清单.md) §6.1 与 [`06-数据采集设计.md`](../技术/06-数据采集设计.md)。

### 6.4 功能边界

| 不做 | 原因 |
|---|---|
| 预测「内定项目」、提前 1-6 月独家预测 | 依赖非公开情报，不属于法定公开数据范畴 |
| 「找关系合作投标」撮合 | 可能构成串通投标，属法律禁止行为 |
| 干预投标资格、评审环节 | 违法 |
| 未经授权转载/再分发公告全文至第三方 | 超出「检索 + 溯源」定位 |

> 待整改的合规项（采集 API 匿名、演示态 `userId` 参数）已在 [4.4 已知缺口与遗留项](#44-已知缺口与遗留项需在二期前处理)中列出，公网部署前必须处理。

### 6.5 数据加工约定（留存边界）

平台**对采集到的数据做加工**，不是把源站页面整页搬进库。适配器在入库前完成「截正文 + 抽字段」两步，**原始详情页 HTML 不入库、不留存**：

| 处理 | 留下 | 丢弃 |
|---|---|---|
| 正文截取 | 公告正文区段（CCGP 取 `#noticeArea`，旧模板兜底 `vF_deail_maincontent`；`ztb_gz` 取源站 `Content` 字段） | 页面骨架（导航、页头页脚、侧栏、面包屑）、`<style>` 样式块、相关推荐位、广告与统计脚本 |
| 字段抽取 | 标题、项目编号、类型、省/市/行业、预算、招标人、代理机构、联系人/电话、发布/截止/开标时间、正文片段、来源与源站 URL | 与业务无关的源站字段（阅读数、内部 ID、模板标记等） |
| 附件 | —— | 招标文件 PDF/Word/ZIP **一律不下载、不存储**（源站 JSON 的 `UploadFile`/`PdfFile` 被有意忽略） |

> ⚠️ 当前已知不足：正文片段**只做区段截取，未做标签白名单清洗**，仍依赖源站自身可信度——与 `tender.xss.enable: false` 是同一取舍，公网部署前应一并评估。技术实现见 [`06-数据采集设计.md`](../技术/06-数据采集设计.md) §4.1、§4.2、§5.4。

| 项目编号 | `notice.projectNo` | 源站给出的项目/招标编号，如 `SXSD2026-AK-056`；辅助人工核对，非唯一键 |
| 预算金额 | `notice.budget` | `decimal`，单位**万元**；源站以「元」发布时入库前 ÷10000 并四舍五入保留 2 位 |
| 采购人 / 招标人 | `notice.tenderPerson` | 发布采购需求的甲方单位。源站字段名各异（`招标人`/`采购人`/`建设单位`/`招标单位`），解析时归一到本字段 |
| 代理机构 | `notice.agency` | 受托组织招标的招标代理机构。`ztb_gz` 无该字段时兜底取源站 `Source`（发布机构） |
| 联系人 | `notice.contact` | 公告公开的项目联系人姓名 |
| 联系电话 | `notice.contactPhone` | 公告公开的联系电话 |
| 地区 | `notice.province`、`notice.city`、`notice.regionCode` | 省 / 市 / 源站地区代码（如 `520100`）。**规则推导**，非源站官方字段，兜底「其他」 |
| 行业 | `notice.industry` | 15 类关键词词典推导（医疗卫生、市政工程、软件服务…），兜底「其他」。**规则推导**，非源站官方字段 |
| 正文 | `notice.content` | 公告正文**富文本片段**（非原始页面），前端 `v-html` 渲染 |
| 截止时间 | `notice.deadline` | 投标截止时间（投标文件递交截止）。CCGP 公开招标中与开标时间同值 |
| 开标时间 | `notice.openTime` | 开标时间 |
| 发布时间 | `notice.publishTime` | 源站公告发布日期；列表默认按此字段倒序 |
| 源站 | `notice.source` | 来源站点名，溯源字段之一 |
| 源站地址 | `notice.sourceUrl` | 源站详情页 URL；**唯一键**（`uk_source_url`），去重与溯源共用 |

### 7.2 公告类型（`NoticeTypeEnum`）

| 中文名 | 代码枚举值 | 说明 | 首页/导航入口 |
|---|---|---|---|
| 招标公告 | `tender` | 公开招标/邀标等采购公告。**仅此类型可在用户端「发起投标」** | 「招标公告」`?type=tender` |
| 中标公告 | `win` | 中标结果公示、成交公告 | 「中标公告」`?type=win` |
| 变更公告 | `change` | 更正、澄清、变更、延期公告 | 「变更公告」`?type=change` |
| 采购公告 | `explore` | 询价、竞争性谈判等采购公告（源站 `xjgg` 频道映射至此） | 「采购公告」`?type=explore` |

> 源频道到类型的映射：`gkzb 公开招标 → tender`、`zbgg 中标公告 → win`、`gzgg 更正公告 → change`、`xjgg 询价公告 → explore`。`ztb_gz` 另有 `BTypeCode` 码表映射，兜底 `BTypeCategory`，再兜底频道配置的 `type`。

### 7.3 采集与数据源

| 中文名 | 代码枚举值 / 字段 | 说明 |
|---|---|---|
| 源适配器 | `SourceAdapter` | 采集扩展点，仅两个方法：`code()` 与 `crawl(site, stats)`。接入新站点 = 实现接口 + `crawler_site` 加一行 |
| 站点 | `crawler_site`（表） | 采集源的配置载体（启用开关、频道 JSON、详情间隔、抓取配置），**DB 驱动，无 YAML 站点配置** |
| 站点标识 | `crawler_site.code` | 与 `SourceAdapter.code()` 一一对应，当前值为 `ccgp`、`ztb_gz` |
| 频道 | `crawler_site.channels`（JSON） | `[{path,name,type,pageCount}]`，一个站点下的多个公告分类入口 |
| 详情间隔 | `crawler_site.intervalMs` | 详情页请求间隔（ms），默认 3000 |
| 采集任务 | `crawler_task`（表） | 一次采集的执行记录与统计 |
| 任务状态 | `RUNNING` / `SUCCESS` / `FAILED`（`CrawlerTaskStatusEnum`） | 超时 4 小时的 `RUNNING` 会被自动置为 `FAILED`（备注「超时自动回收」） |
| 两段式采集 | — | 列表页取候选 → 详情页取字段，两个阶段解耦 |
| 去重 | `uk_source_url` | 以 `source_url` 为唯一键，新记录 INSERT、已有记录按字段差异 UPDATE |

### 7.4 用户与投标

| 中文名 | 代码枚举值 / 字段 | 说明 |
|---|---|---|
| 会员 | `member_user`（表）、`UserTypeEnum.MEMBER` | 用户端账号主体，与后台管理员（`system_users`）分属不同令牌类型 |
| 用户端 | `/app-api/**` | 会员接口前缀，由包名规则 `**.controller.app.**` 决定 |
| 管理端 | `/admin-api/**` | 管理后台接口前缀，由包名规则 `**.controller.admin.**` 决定 |
| 令牌 | OAuth2 access token | 会员令牌与后台令牌**不通用**：过滤器会比对令牌 `userType` 与 URL 前缀推导出的用户类型，不匹配即拒 |
| 投标项目 | `bid_project`（表） | 本企业针对某条标讯发起的投标记录，冗余 `projectName` 与 `deadline` |
| 拟投标金额 | `bid_project.bidAmount` | `decimal`，单位万元 |
| 投标状态 | `SUBMITTED` / `OTB` / `WON` / `LOST` / `ABANDONED`（`BidProjectStatusEnum`） | 见下表 |
| 状态机守卫 | `BidProjectStatusEnum.allowed(from, to)` | 仅放行白名单迁移，终态不可再变更 |

投标状态流转：

| 状态 | 中文 | 允许迁移到 |
|---|---|---|
| `SUBMITTED` | 已递交 | `OTB`（待开标）、`ABANDONED`（放弃） |
| `OTB` | 待开标 | `WON`（中标）、`LOST`（未中标）、`ABANDONED` |
| `WON` | 中标 | 终态 |
| `LOST` | 未中标 | 终态 |
| `ABANDONED` | 放弃 | 终态 |
