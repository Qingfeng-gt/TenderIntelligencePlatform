# 平台设计 —— 招投标数据采集与投标平台（DEMO 一期）

> 编制：2026-09-08
> 依据：`doc/调研实录-页面拆解与数据库设计.md`（千里马/剑鱼/政府采购网对照）+ 环境实测（WSL）
> 本期目标：**可跑的 DEMO** —— 自动化爬取公开招标数据 → 提取入库 → 用户端随时浏览 → 用户进行招投标

---

## 一、范围与定位

DEMO 一期闭环（唯一优先）：

```
真实源站 ──爬虫──▶ 提取/归一化 ──▶ notice 表 ──▶ user-web 公告浏览(已有) ──▶ 发起投标 ──▶ bid_project 状态流转
```

一期不做：会员/支付、AI 标书、订阅推送正式版（二期；架构上预留）。
说明：投标流程在 DEMO 中为「项目管理闭环」：平台定位是**投标管理工具**（真实递交到公共资源交易平台需 CA 数字证书，属线下动作），DEMO 以「报名 → 递交文件 → 开标 → 中标/未中标」状态机模拟。

## 五、数据模型

### 5.1 notice（扩展，已有表）

```sql
ALTER TABLE `notice` ADD COLUMN `project_no`     varchar(128) DEFAULT ''  COMMENT '项目编号(源站,如 SXSD2026-AK-056)';
ALTER TABLE `notice` ADD COLUMN `source_url`     varchar(512) NOT NULL DEFAULT '' COMMENT '源站详情 URL';
ALTER TABLE `notice` ADD COLUMN `deadline`       datetime DEFAULT NULL  COMMENT '投标截止时间';
ALTER TABLE `notice` ADD COLUMN `open_time`      datetime DEFAULT NULL  COMMENT '开标时间';
ALTER TABLE `notice` ADD COLUMN `region_code`    varchar(16) DEFAULT ''  COMMENT '源站地区代码(如 610000)';
ALTER TABLE `notice` ADD UNIQUE KEY `uk_source_url` (`source_url`);
```

- 去重：以 `source_url` 为唯一键；项目编号辅助人工核对。
- `type` 映射（源频道 → 平台类型）：`gkzb 公开招标→tender`、`zbgg 中标公告→win`、`gzgg 更正公告→change`、`xjgg 询价公告→explore`。

## 六、爬虫设计（核心）

**两段式采集**，避免列表与详情耦合过度：

1. `listPage`：按频道 `channels` 循环抓取列表页（`pageCount` 默认第一页），解析出 `[{detailUrl, title, city？, publishTime？}]` 候选集。
2. `detailPage`：对候选集逐个抓详情（`interval_ms` 限速，默认 3s），解析字段。
3. 入库：`source_url` 未存在 → INSERT；存在 → 只更新变更字段（标题/截止时间/正文），计入 `updated`。

**提取规则（CcgpAdapter，实测字段锚点）**：

| 字段 | 提取方式（实测 HTML） |
|---|---|
| 标题 | `<h2 class="tc">…</h2>` |
| 正文 | `<div id="noticeArea">…</div>`（保留 HTML，前端 v-html 渲染） |
| 项目编号 | `项目编号：([^<]+)` |
| 预算金额 | `预算金额：([\d,\.]+)元` → decimal 万元 |
| 采购人 | `noticePurchase-purchaserOrgName` 的 span |
| 代理机构 | `noticeAgency-agencyName` 的 span |
| 联系人/电话 | `项目联系人：` / `noticePurchase-purchaserLinkTel` |
| 投标截止 | `class="…bidFileSubmitTime3…"` 内日期（2026年09月28日 09时00分00秒） |
| 开标地点 | `noticeBidTime-bidAddress` |
| 发布时间 | 页面底部 `<p name="releaseDateSpan">2026年09月08日</p>`（或列表页日期） |
| 省/市 | 标题规则提取：`[^市]{2,8}市/省` + 内置「省/市词表」映射（city→province），未命中则根据正文「安康市汉滨区」类规则补充 |
| 行业 | 关键词词典（医疗/医院→医疗卫生、道路/管网/市政→市政工程、数据/系统/软件→软件服务…），兜底「其他」 |

**反爬与合规**（DEMO 实现）：
- UA 使用浏览器 UA；首次访问首页拿 Cookie 后再访问列表/详情（实测必须，否则 403/限流）。
- 详情页间隔 ≥3s（可配）；仅抓**公告正文页**，不抓附件文件。
- 数据为政府公开信息，保留 `source` + `source_url` 溯源，不做知识产权数字化传播；遵守 robots 约定，控制频率。

**调度**：默认「手动触发」（`POST /admin-api/crawler/run`，管理脚本/页面调用），`@Scheduled` 定时功能通过 `tender.crawler.schedule-cron` 配置项开关（二期数据量上来后交给 Quartz/XXL-Job）。

## 七、用户招投标（DEMO 流程）

```
公告详情页[发起投标] → POST /bid-project/create(预填公告信息+投标金额)
    → 我的投标列表 MyBidsPage
        SUBMITTED已递交 ──[标记开标]──▶ OTB待开标
        OTB待开标 ──[确认中标]──▶ WON中标  ──[未中标]──▶ LOST未中标
        任意态 ──[放弃项目]──▶ ABANDONED放弃
```

- 状态校验：仅允许合法迁移（demo 校验简化为「终态不可再变更」+ 白名单对子表）。
- 演示用户：无登录态，接口以请求参数 `userId` 标识（默认 1），**正式版替换为会员 token 鉴权**（见预算八）。
- 与公告联动（二期）：win 类型公告按 `source`/标题规则匹配 bid_project 自动置 WON/LOST 并写入时间线。

## 八、二期预留（本 DEMO 不做，仅设计定位）

| 能力 | 接入点 |
|---|---|
| 会员服务 | 启用 pom 已注释的 `tender-module-member` + `tender-module-pay`；bid_project.user_id 换成会员 ID；权益拦截器按套餐限制投标/AI 次数 |
| AI 一键标书 | 复用 `tender-module-ai`：招标文件 PDF 解析 → 企业素材知识库(RAG) → 模板生成 → Word 导出；输入源正是 crawler 详情页附件 |
| 订阅推送 | 订阅规则表 + 匹配引擎 + WebSocket/站内信；变更记录表 `notice_change_log` 做「修改内容」时间线 |
| 更多源站 | 实现新 `SourceAdapter`（千里马列表模板、各省平台）+ 配置加 `crawler_site` 行即可，核心不变 |
