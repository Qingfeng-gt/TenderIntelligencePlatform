## 一、约定与总览

### 1.1 URL 前缀：由包名自动派生，不是手写

前缀不是在各 Controller 的 `@RequestMapping` 里写的，而是由框架在注册 `RequestMappingHandlerMapping` 时按**包名谓词**注入（`tender-framework/tender-spring-boot-starter-web/.../config/TenderWebAutoConfiguration.java`）：

```java
private Api appApi   = new Api("/app-api",   "**.controller.app.**");
private Api adminApi = new Api("/admin-api", "**.controller.admin.**");
```

| 包路径 | 注入前缀 | 配置文件键 |
|---|---|---|
| `com.tenderintelligence.module.*.controller.**admin**.**` | `/admin-api` | `tender.web.admin-api.prefix` |
| `com.tenderintelligence.module.*.controller.**app**.**` | `/app-api` | `tender.web.app-api.prefix` |

**推论（联调必读）**：同一个 `@RequestMapping("/notice")` 写在 `controller.admin.notice` 包里，最终地址是 `/admin-api/notice`；写在 `controller.app.auth` 包里就是 `/app-api/member/auth`。本项目中 `bid` 模块**曾在两个包里各写一份控制器**（`/admin-api/bid-project` 与 `/app-api/bid-project`）；管理端那份已于 2026-09-11 删除，现只存 `/app-api/bid-project` —— 详见 2.3。

### 1.2 统一响应体 `CommonResult`

`tender-framework/tender-common/src/main/java/com/tenderintelligence/framework/common/pojo/CommonResult.java`

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | `Integer` | 业务码，**`0` 为成功**（`GlobalErrorCodeConstants.SUCCESS`）；非 0 即为失败 |
| `msg` | `String` | 错误提示，成功时为空串 `""`（`success()` 显式置空，非 null） |
| `data` | `T` | 业务数据，失败时为 null |

常用非 0 码（`GlobalErrorCodeConstants`）：`400` 请求参数不正确、`401` 账号未登录、`403` 没有该操作权限、`404` 请求未找到、`429` 请求过于频繁、`500` 系统异常、`501` 功能未实现/未开启。

### 1.3 分页请求与响应

**请求**（`PageParam`，继承后作为 `@Valid` 的查询参数对象）：

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| `pageNo` | `Integer` | 是 | `1` | `@Min(1)` |
| `pageSize` | `Integer` | 是 | `10` | `@Min(1) @Max(200)`；`-1` 表示不分页（`PageParam.PAGE_SIZE_NONE`） |

**响应**（`PageResult<T>`）：仅两个字段。

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | `Long` | 总量 |
| `list` | `List<T>` | 当前页数据 |

注意：分页响应**没有** `pageNo`/`pageSize` 回显，前端需自行保存请求值。

### 1.4 时间与长整型序列化

- `application.yaml`：`spring.jackson.serialization.write-dates-as-timestamps: true`，且 `tender-framework/tender-spring-boot-starter-web/.../jackson/config/TenderJacksonAutoConfiguration.java` 将 `LocalDateTime` 全局替换为 `TimestampLocalDateTimeSerializer` / `TimestampLocalDateTimeDeserializer`。
- **结论**：所有 `LocalDateTime` 字段（`publishTime`、`deadline`、`openTime`、`startTime`、`endTime`、`createTime`、`expiresTime` 等）在 JSON 里都是 **epoch 毫秒数值**，不是字符串。前端必须用统一的 `utils/format` 处理，直接 `new Date(str)` 会得到 `Invalid Date`。
- `Long` 也经 `NumberSerializer` 序列化，避免前端精度丢失。

### 1.5 鉴权与令牌

- `tender-framework/tender-spring-boot-starter-security/.../config/TenderWebSecurityConfigurerAdapter.java`：启动时扫描全部 `@PermitAll`（方法级或类级）构建放行清单，叠加 `tender.security.permit-all-urls`，最后 `anyRequest().authenticated()`。**未显式放行的一律需要有效令牌**。
- 令牌取值位置（`SecurityProperties`）：Header `Authorization`（`tokenHeader`）或查询参数 `token`（`tokenParameter`）。
- `.../core/filter/TokenAuthenticationFilter.java` 会把**令牌里的 `userType` 与 URL 前缀推导出的用户类型比对**，不一致抛 `AccessDeniedException("错误的用户类型")`。这是 `/admin-api`（后台管理员）与 `/app-api`（`UserTypeEnum.MEMBER`）令牌隔离的落地机制。
- 开发态 mock 登录：`tender.security.mock-enable=true` 且令牌为 `mockSecret + 用户id`（local profile 下 `mock-enable: true`、`mockSecret: test`，即令牌传 `test1` 即模拟用户 1）。

### 2.2 tender-module-crawler（数据采集）

**定位**：站点配置驱动的两段式（列表页 → 详情页）采集、解析、去重入库。依赖 `tender-module-notice`（写 `notice` 表）。表：`crawler_site`、`crawler_task`。

**控制器**：`tender-module-crawler/src/main/java/com/tenderintelligence/module/crawler/controller/admin/crawler/CrawlerController.java`

类级注解：`@Tag("数据采集中心")`、`@RestController`、`@TenantIgnore`、`@RequestMapping("/crawler")`、`@Validated`。
类 Javadoc 原文：`招投标数据采集 - 管理接口`，并注明「需管理员令牌：触发采集与读取采集日志均为后台运维动作，不对外开放」。

> ⚠️ **2026-09-11 鉴权整改**：4 个端点原均为 `@PermitAll`（匿名可触发采集、匿名可读全部采集日志）。现已全部去除，**需管理员令牌**；匿名调用返回 `{"code":401,"msg":"账号未登录"}`。管理端 `admin-web` 无需改动 —— 其 `src/api/crawler/index.ts` 走 `config/axios` 的 `request` 实例，`service.ts:57` 会自动附加 `Authorization: Bearer <token>`。

| HTTP 方法 | 完整路径 | 匿名 | 请求参数 | 响应（data） | 说明 |
|---|---|---|---|---|---|
| POST | `/admin-api/crawler/run` | 否（需管理员令牌） | `siteCode:String:否:站点标识，缺省采集所有启用站点` | `Long`（任务编号） | **异步**：立即返回首个任务 id，后台串行执行；若目标站点已有 RUNNING 任务则跳过，可能返回 `null` |

**`CrawlerSiteRespVO`**：`id`、`name`、`code`、`enabled`(Boolean)、`channels`(JSON 字符串)、`intervalMs`。注意 **`config` 字段不下发**（含 UA 等）。

**Service**：`.../service/CrawlService.java`（实现 `.../service/impl/CrawlServiceImpl.java`，`@Service`）

```java

List<CrawlerSiteDO>     getSiteList();
PageResult<CrawlerTaskDO> getTaskPage(PageParam pageParam, String siteCode);
CrawlerTaskDO           getLatestTask(String siteCode);
```

`run` 的关键语义：先 `failStaleTasks(Duration.ofHours(4))` 回收超时 RUNNING 任务 → 单站点时校验存在性与 `enabled`（否则抛 `CRAWLER_SITE_NOT_EXISTS` / `CRAWLER_SITE_DISABLED`）；未指定时取全部 `enabled != false` 的站点 → 逐站点 `selectRunningCount > 0` 则跳过（防重入）→ 建 `CrawlerTaskDO`（状态 `RUNNING`）→ 提交至**单线程守护线程池**（线程名 `crawler-run`，串行化以免打爆源站）。执行失败时 `errorMsg` 截断至 500 字符。


`createBidProject` 流程：读源公告（不存在抛 `NOTICE_NOT_EXISTS`）→ `selectActiveByUserAndNotice` 判重 → 冗余 `title`→`projectName`、`deadline`→`deadline` → 状态置 `SUBMITTED`。
`getBidProject` 归属校验：`userId != null && !bidProject.getUserId().equals(userId)` 时抛 `BID_PROJECT_NOT_EXISTS`（**用「不存在」而非「无权限」，避免探测他人数据是否存在**）。

#### 状态机

`.../enums/BidProjectStatusEnum.java` —— 迁移表硬编码在 `TRANSITIONS`（`Map<String, Set<String>>`），守卫是 `static boolean allowed(String from, String to)`，未知 `from` 走 `getOrDefault(from, Set.of())` 返回空集；`static resolve(String)` 未知状态返回 `null`。

| 状态 | 含义 |
|---|---|
| `SUBMITTED` | 已递交 |
| `OTB` | 待开标 |
| `WON` | 中标 |
| `LOST` | 未中标 |
| `ABANDONED` | 放弃 |

**合法迁移表**：

| from | 允许的 to |
|---|---|
| `SUBMITTED` | `OTB`、`ABANDONED` |
| `OTB` | `WON`、`LOST`、`ABANDONED` |
| `WON` | 无（终态） |
| `LOST` | 无（终态） |
| `ABANDONED` | 无（终态） |

```
        createBidProject
               │
               ▼
        ┌─────────────┐
        │  SUBMITTED  │ 已递交
        └──┬───────┬──┘
     OTB ◄─┘       └─► ABANDONED(终态)
      │                     ▲
  ┌───┴────┐                │
  ▼        ▼                │
 WON      LOST              │
(终态)   (终态)             │
  └────────┴────────────────┘
   （OTB 也可直接 ABANDONED）
```

- **非法迁移**（含从终态再迁移、跳级如 `SUBMITTED → WON`、目标状态拼写错误）统一抛 `BID_PROJECT_STATUS_ILLEGAL`。
- **重复在途投标**：`BidProjectMapper.selectActiveByUserAndNotice(userId, noticeId)` 的判据是 `status IN ('SUBMITTED', 'OTB')`（源码中为字面量字符串，未引用枚举常量），命中即抛 `BID_PROJECT_ALREADY_EXISTS`。**即：同一用户对同一公告只能有一个「在途」项目；`WON`/`LOST`/`ABANDONED` 之后可再次发起。**

#### DO → 表

`.../dal/dataobject/BidProjectDO.java` → `@TableName("bid_project")`、`@KeySequence("bid_project_seq")`，继承 `BaseDO`。字段：`id`、`userId`（注释「演示默认1,正式接会员」）、`noticeId`、`projectName`（冗余自公告）、`deadline`（冗余自公告）、`bidAmount`、`bidFileName`、`status`、`remark`。

**Mapper**：`.../dal/mysql/BidProjectMapper.java`：`selectListByUser(userId, status)`（按 `createTime` 倒序）、`selectActiveByUserAndNotice`、`selectCountByUser`（当前无调用方）。

| `BID_PROJECT_NOT_EXISTS` | `1_070_100_000` | 投标项目不存在 |

### 2.4 tender-module-member（会员认证）

**定位**：用户端门户账号体系，独立于后台 `system_users`。依赖 `tender-module-system`（复用其 OAuth2 令牌、登录日志、验证码）。表：`member_user`。

**控制器**：`tender-module-member/src/main/java/com/tenderintelligence/module/member/controller/app/auth/MemberAuthController.java`

类级：`@Tag("用户端 - 会员认证")`、`@RequestMapping("/member/auth")`、`@Validated`、`@TenantIgnore`。
Javadoc：`挂载在 /app-api 前缀,令牌类型为 MEMBER,与后台 admin-api 互相隔离`。

| HTTP 方法 | 完整路径 | 匿名 | 请求参数 | 响应（data） | 说明 |
|---|---|---|---|---|---|
| POST | `/app-api/member/auth/login` | 是（`@PermitAll`） | Body `MemberLoginReqVO`：`username`、`password`、`captchaVerification` | `AppAuthLoginRespVO` | 校验验证码 → BCrypt 校验密码 → 签发令牌 |
| POST | `/app-api/member/auth/register` | 是（`@PermitAll`） | Body `MemberRegisterReqVO`：`username`、`password`、`nickname`、`captchaVerification` | `AppAuthLoginRespVO` | 用户名唯一校验后创建，**注册成功即自动登录** |
| POST | `/app-api/member/auth/logout` | 是（`@PermitAll`） | Header `Authorization` 或参数 `token` | `Boolean`（恒 `true`） | 令牌为空时静默成功，不报错 |
| GET | `/app-api/member/auth/get-profile` | **否（无 `@PermitAll` → 需有效令牌）** | 无（身份取自令牌） | `MemberProfileRespVO` | 会员不存在抛 `AUTH_MEMBER_NOT_EXISTS` |

**VO 字段**

| VO | 字段 |
|---|---|
| `MemberLoginReqVO extends CaptchaVerificationReqVO` | `username`（`@NotEmpty`，长度 4–30）、`password`（`@NotEmpty`，长度 4–16）；父类：`captchaVerification`（验证码开启时 `@NotEmpty`） |
| `MemberRegisterReqVO extends CaptchaVerificationReqVO` | `username`（4–30）、`password`（4–16）、`nickname`（≤30，可空）；父类同上 |
| `AppAuthLoginRespVO` | `userId`、`accessToken`、`refreshToken`、`expiresTime`（epoch 毫秒） |
| `MemberProfileRespVO` | `id`、`username`、`nickname`、`mobile`、`avatar`（**不含 password/status/loginIp**） |

**Service**

`.../service/auth/MemberAuthService.java`（实现 `MemberAuthServiceImpl`）：

```java
AppAuthLoginRespVO   login(MemberLoginReqVO reqVO);
AppAuthLoginRespVO   register(MemberRegisterReqVO reqVO);
void                 logout(String token);              // oauth2TokenService.removeAccessToken
MemberProfileRespVO  getProfile(Long userId);           // 会员不存在抛 AUTH_MEMBER_NOT_EXISTS
```

`.../service/user/MemberUserService.java`（实现 `MemberUserServiceImpl`）：

```java
MemberUserDO  getUser(Long id);
MemberUserDO  getUserByUsername(String username);
MemberUserDO  createUser(MemberRegisterReqVO registerReqVO);  // BCrypt 编码；昵称空则默认=用户名；状态 ENABLE
void          updateUserLogin(Long id, String loginIp);       // 同时写 loginDate
```

**令牌机制（必须讲清）**：登录/注册成功后走

```java
oauth2TokenService.createAccessToken(user.getId(),
        UserTypeEnum.MEMBER.getValue(),               // = 1，面向 c 端
        OAuth2ClientConstants.CLIENT_ID_DEFAULT, null);
```

即**令牌是 `system` 模块签发的标准 OAuth2 访问令牌**，用户类型为 `UserTypeEnum.MEMBER`。`TokenAuthenticationFilter` 会把令牌里的 `userType` 与 `/app-api` 前缀推导出的 `MEMBER` 比对，因此**会员令牌无法访问 `/admin-api/**`（会因「错误的用户类型」被拒），后台令牌也无法访问 `/app-api/**`**。登录日志经 `LoginLogService` 写入，`userType` 同样为 `MEMBER`。

**验证码开关**：`@Value("${tender.captcha.enable:true}")` 注入（`MemberAuthServiceImpl`），关闭时 `doValidateCaptcha` 直接返回成功、且跳过 `CodeEnableGroup` 参数校验；实现为 anji `CaptchaService`（`aj.captcha.type: blockPuzzle` 滑块）。**基础 yaml 未设该键（默认 true），`application-local.yaml` 显式 `tender.captcha.enable: false`** —— 本机联调登录接口时**不需要**传 `captchaVerification`。

**DO → 表**：`.../dal/dataobject/MemberUserDO.java` → `@TableName("member_user")`、`@KeySequence("member_user_seq")`。字段：`id`、`username`、`password`(BCrypt)、`nickname`、`mobile`、`avatar`、`status`(0 正常 / 1 停用)、`loginIp`、`loginDate`。

**Mapper**：`.../dal/mysql/MemberUserMapper.java`：`selectByUsername(String)`。

**错误码**：`.../enums/ErrorCodeConstants.java`（区间注释：`[1-004-000-000 ~ 1-005-000-000)`）

| 常量 | 值 | 含义 |
|---|---|---|
| `AUTH_REGISTER_USERNAME_EXISTS` | `1_004_000_001` | 注册用户,用户名已存在 |
| `AUTH_MEMBER_NOT_EXISTS` | `1_004_000_002` | 会员不存在 |
| `MEMBER_USER_NOT_EXISTS` | `1_004_001_000` | 会员用户不存在（**当前源码中无任何调用方，仅声明**） |

**登录复用 system 错误码**（`MemberAuthServiceImpl` 静态导入 `module.system.enums.ErrorCodeConstants`）：`AUTH_LOGIN_BAD_CREDENTIALS = 1_002_000_000`（账号密码不正确）、`AUTH_LOGIN_USER_DISABLED = 1_002_000_001`（账号被禁用）、`AUTH_LOGIN_CAPTCHA_CODE_ERROR = 1_002_000_004`（验证码不正确，原因：`{}`）。

## 五、联调速查

**匿名端点（无需令牌）**

```
GET  /admin-api/notice/list?pageNo=1&pageSize=10&type=tender&keyword=市政
GET  /admin-api/notice/get?id=1
GET  /admin-api/notice/stats
POST /app-api/member/auth/login       (local 环境验证码关闭，仅需 username/password)
POST /app-api/member/auth/register
POST /app-api/member/auth/logout
```

**需令牌端点**

```
GET  /app-api/member/auth/get-profile          # MEMBER 令牌
*    /app-api/bid-project/{create,list,get,status}   # MEMBER 令牌
*    /admin-api/crawler/{run,site/list,task/page,task/latest}  # 管理员令牌(2026-09-11 起，原为匿名)
```

**本地直达（mock 登录）**：local 环境 `tender.security.mock-enable=true`、`mockSecret=test`，直接以 `Authorization: test1` 即可模拟「用户 1」调用 `/app-api/**` 与 `/admin-api/**`，无需先走登录。

**常踩的坑**

1. 所有时间为 **epoch 毫秒**，前端统一走 `utils/format`。
2. 分页响应只有 `total` / `list`，没有 `pageNo` / `pageSize` 回显。
3. 成功响应的 `msg` 是空串 `""`，判成功请用 `code === 0`，不要判 `msg` 非空。
4. `POST /admin-api/crawler/run` 是**异步**的，且站点已有 RUNNING 任务时**返回 `null` 且不报错**。
5. `bid` 的 `status` 流转非法时返回 `1_070_100_002`；重复在途投标返回 `1_070_100_001`。
6. 会员令牌调 `/admin-api/**` 会被拒（「错误的用户类型」），反之亦然 —— 这是设计如此，不是 bug。
