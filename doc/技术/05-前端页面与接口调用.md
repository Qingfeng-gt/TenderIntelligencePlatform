## 一、两个前端的分工

本项目有两个**完全独立**的 Vue 3 工程，不共享任何代码或依赖包：

| 工程 | 定位 | 使用者 | 品牌/名称 | 开发端口 | 技术栈版本 |
|---|---|---|---|---|---|
| `user-web/` | 用户门户（标讯检索 + 投标） | 投标企业、供应商等**外部用户** | 「标讯通」（**暂定名**，该名已被他人使用，见 [`README.md`](../README.md) 命名说明） | 3001 | vue 3.5.13 / element-plus 2.9.3 / vite 6 |
| `admin-web/` | 管理后台 | 平台**运营人员** | `tender-admin-web` | 80 | vue 3.5.34 / element-plus 2.13.7 / vite 8 |

**为什么要分成两个**：

1. **鉴权体系不同** —— 用户端打 `/app-api`（会员令牌），管理端打 `/admin-api`（后台用户令牌），后端按前缀强制隔离（见 [`03-系统架构.md`](03-系统架构.md) §四）。
2. **技术选型不同** —— 用户端刻意保持轻量（无 UnoCSS、无 i18n、无 echarts，手写 CSS）；管理端沿用脚手架的全套基建（UnoCSS、sass、vue-i18n、echarts、`useTable`/`useCrudSchemas` 等封装）。
3. **发布形态不同** —— 用户端面向公网，管理端通常内网部署或加访问控制。

**两者唯一的共同点**：都通过 Vite 代理/直连把请求打到同一个后端 `127.0.0.1:48080`，以及 Element Plus 的中文 locale。

### 2.5 API 层（关键：两个 axios 实例）

**这是用户端最容易踩坑的地方** —— 请求分两类，用两个不同的 axios 实例：

#### 实例 A：`api/request.ts`（匿名接口）

| 项 | 值 |
|---|---|
| `baseURL` | `/admin-api` |
| 超时 | 15000 ms |
| 请求拦截器 | **无** —— 不附加任何鉴权头 |
| 响应拦截器 | 解包 `body.data`；`body.code !== 0` 则 reject |

用于**公开的标讯查询**。后端这三个接口本身是 `@PermitAll`，不需要令牌。

#### 实例 B：`api/app-request.ts`（会员接口）

| 项 | 值 |
|---|---|
| `baseURL` | `/app-api` |
| 超时 | 15000 ms |
| 请求拦截器 | 附加 `Authorization: Bearer <getToken()>` |
| 响应拦截器 | 解包 `body.data`；`code !== 0` 则 reject；**HTTP 401 → `clearAuth()` + `location.replace('/login?redirect=…')`** |

用于**需要会员身份的登录、注册、投标**。

> **为什么必须分开**：后端的 `TokenAuthenticationFilter` 会比对令牌的 `userType` 与 URL 前缀。会员令牌（`MEMBER`）打 `/app-api` 才合法；若误把会员令牌塞进 `/admin-api` 请求（或反之），后端直接拒绝。这是刻意设计的隔离，用两个 axios 实例来落实。

#### 接口清单

| 文件 | 导出函数 | 方法 + URL（相对 base） |
|---|---|---|
| `api/notice.ts` | `listNotices(query)` | `GET /notice/list`，参数 `pageNo, pageSize, keyword, type, province, industry, publishTimeGreaterThan` |
| | `getNoticeDetail(id)` | `GET /notice/get?id=` |
| | `getHomeStat()` | `GET /notice/stats` |
| | `getAllIndustries()` | **本地函数，无 HTTP** —— 返回硬编码的 15 个行业字符串 |
| | `hotTags` | **本地常量** —— 8 个 `{name, count}` 热词 |
| | （内部 `toTimeParam`） | 把 `''`/`'today'`/`'week'`/`'month'` 转成 `yyyy-MM-dd HH:mm:ss` 字符串 |
| `api/auth.ts` | `memberLogin({username,password,captchaVerification?})` | `POST /member/auth/login` |
| | `memberRegister({username,password,nickname?,captchaVerification?})` | `POST /member/auth/register` |
| | `memberLogout()` | `POST /member/auth/logout` |
| | `getMemberProfile()` | `GET /member/auth/get-profile` |
| `api/bid.ts` | `createBidProject({noticeId,bidAmount?,bidFileName?,remark?})` | `POST /bid-project/create` |
| | `listBidProjects(status?)` | `GET /bid-project/list?status=` |
| | `updateBidStatus(id,status)` | `POST /bid-project/status` |
| `api/captcha.ts` | `getCode(data)` | 裸 `axios.post('/admin-api/system/captcha/get')` |

> **`api/captcha.ts` 为什么用裸 axios**：后端验证码接口返回的是 AJ-Captcha 协议格式（`{repCode, repMsg, repData}`），不符合本项目 `{code, data, msg}` 的统一响应约定，走拦截器会被判为失败，因此绕过。

> **注意 `api/bid.ts` 不带 userId**：投标接口的会员身份完全由 `Authorization` 头承载，前端不传 userId。这是正确的做法 —— 后端 `BidPortalController` 从令牌取身份，不允许通过参数伪造（对比 admin 侧的 `BidProjectController` 用查询参数传 userId，见 [`04-后端模块与接口.md`](04-后端模块与接口.md) §四）。

### 2.7 时间格式化（重要约定）

`user-web/src/utils/format.ts`：

| 函数 | 输出 |
|---|---|
| `parseTime(v)` | 内部解析，兼容 **epoch 毫秒数字** 与 **ISO 字符串** |
| `formatDateTime(v)` | `YYYY-MM-DD HH:mm` |
| `formatDateTimeShort(v)` | `MM-DD HH:mm`（列表页用） |

空值统一渲染为 `'—'`。

> ⚠️ **为什么需要兼容两种格式**：后端 Jackson 配置为 `write-dates-as-timestamps: true`，`LocalDateTime` 会被序列化成**epoch 毫秒数字**（如 `1786000000000`）而不是字符串。前端若直接用字符串处理会全部显示为 `NaN` 或错乱 —— 这是项目历史上踩过的坑，所有时间展示必须走这个工具函数。

### 3.4 请求封装与鉴权

`admin-web/src/config/axios/service.ts`：

- **请求拦截**：`isToken` 默认 `true`（URL 含 `/login` 或 `/refresh-token` 的白名单强制 `false`），然后统一设 `config.headers.Authorization = 'Bearer ' + getAccessToken()`。
- **令牌存储**：`web-storage-cache` 的 `ACCESS_TOKEN` / `REFRESH_TOKEN`（`admin-web/src/utils/auth.ts` 的 `setToken`/`getAccessToken`/`getRefreshToken`/`removeToken`/`formatToken`）。
- **租户头**：`tenant-id`、`visit-tenant-id` 由 `import.meta.env.VITE_APP_TENANT_ENABLE` 门控 —— 当前 `.env` 中为 `false`，即**不再发送租户头**。
- **请求体加密**：由 `isEncrypt` 头触发 `ApiEncrypt.encryptRequest`（`admin-web/src/utils/encrypt.ts`）；响应按 `X-Api-Encrypt` 头解密；`postOriginal` 绕过。当前后端 `tender.api-encrypt.enable: false`，该链路未启用。
- **响应处理**：`code === 401` → 静默刷新令牌并重放请求（`requestList` 队列）；无 refreshToken 则 `handleAuthorized()`（确认框 → `resetRouter()` + `deleteUserCache()` + `removeToken()` + 硬刷新）。`500`/`901` 特殊处理。成功判定为 `code === 0 || code === 200`。Blob/arraybuffer 响应直接返回原始数据（供 Excel 导出）。

### 3.5 数据采集中心页面（`crawler/index.vue`）

这是管理端**唯一的业务功能页**，也是采集系统的主要操作入口。组件名 `CrawlerCenter`，由 `system_menu` id `12800` 下发（path `/crawler`，component `crawler/index`，icon `ep:data-analysis`）。

**上半部分 —— 站点卡片网格**：每个启用站点一张 `el-card`，展示：

| 展示项 | 数据来源 |
|---|---|
| 站点名称 / 站点 code | `GET /crawler/site/list` |
| 启用/停用标签 | 同上（`enabled`） |
| 频道数 | 同上（前端解析 `channels` JSON 取长度） |
| 最近任务状态标签 | `GET /crawler/task/latest?siteCode=` |
| 最近新增/更新条数 | 同上（`newInsert` / `updated`） |
| 结束时间 | 同上（`endTime`） |
| 「立即采集」按钮 | `POST /crawler/run?siteCode=` |

顶部另有「采集全部」「刷新」按钮（前者对应不带 siteCode 的 `POST /crawler/run`）。

**下半部分 —— 任务日志表**：站点下拉筛选 + `el-table` + `Pagination`。

| 列 | 字段 |
|---|---|
| 任务编号 | `id` |
| 站点 | `siteCode` |
| 状态 | `status`（`RUNNING`/`SUCCESS`/`FAILED` → 执行中/成功/失败） |
| 列表·解析 | `listFetched` / `listParsed` |
| 详情·失败 | `detailFetched` / `detailFailed` |
| 新增·更新 | `newInsert` / `updated` |
| 开始 / 结束 | `startTime` / `endTime` |
| 错误信息 | `errorMsg` |

**轮询**：页面每 **5 秒**轮询一次最近任务状态（`setInterval`，在 `onBeforeUnmount` 清理），以便实时看到采集进度滚动。

**对应 API 文件** `admin-web/src/api/crawler/index.ts`：

| 函数 | 方法 + URL | 类型 |
|---|---|---|
| `getCrawlerSiteList()` | `GET /crawler/site/list` | `CrawlerSiteVO` |
| `getCrawlerTaskPage(params)` | `GET /crawler/task/page` | `CrawlerTaskVO` |
| `getCrawlerLatestTask(siteCode)` | `GET /crawler/task/latest?siteCode=` | `CrawlerTaskVO` |
| `runCrawler(siteCode?)` | `POST /crawler/run?siteCode=` | `number`（任务 id） |

### 3.7 组件与工具约定

- **全局组件**（`admin-web/src/components/index.ts` 注册）：`ContentWrap`、`Table`、`Form`、`Search`、`Dialog`、`Pagination`、`Icon`、`Echart`、`DictTag`、`ContentDetailWrap`、`Crontab`、`Infotip`、`DocAlert`、`OperateLogV2`、`ShortcutDateRangePicker` 等。
- **表格**：`@/hooks/web/useTable` + `useCrudSchemas` 封装了分页、查询、增删改查流程。
- **字典**：`@/utils/dict` 的 `getIntDictOptions` / `getBoolDictOptions` / `DICT_TYPE`。
- **权限指令**：`v-hasPermi`（`admin-web/src/directives/permission`）。
- **时间格式化**：`admin-web/src/utils/formatTime.ts` —— 基于 dayjs，提供 `formatDate`（默认 `YYYY-MM-DD HH:mm:ss`）、`formatNullableDate`、`formatPast`（刚刚/N 分钟前/…）、`formatSeconds`、`dateFormatter`/`dateFormatter2`（供 el-table `formatter`）、`defaultShortcuts`（el-date-picker 快捷区间）、`getLast7Days`/`getLast30Days`/`getDateRange`/`getMonthRange`、`beginOfDay`/`endOfDay`/`betweenDay`/`addTime`/`isSameDay`。另有 `utils/{formatter,dateUtil,cron}.ts`、`hooks/web/{useTimeAgo,useNow}.ts`。

> ⚠️ **两套时间工具不共享**：`user-web` 用自己手写的 `utils/format.ts`，`admin-web` 用 dayjs 的 `utils/formatTime.ts`。修改时间展示行为时注意别只改一边。

## 四、两端对照速查

| 维度 | user-web | admin-web |
|---|---|---|
| 面向 | 外部会员用户 | 平台运营 |
| 端口 | 3001（Vite 代理到 48080） | 80（**直连** `localhost:48080`） |
| 请求前缀 | `/admin-api`（公开数据）+ `/app-api`（会员数据） | `/admin-api` |
| 鉴权 | 手动在 axios 实例上附加 `Bearer`；localStorage | 拦截器统一附加 `Bearer`；`web-storage-cache` + 刷新令牌 |
| 令牌类型 | `MEMBER` | 后台用户 |
| 路由 | 静态，写死在 `router/index.ts` | 动态，由 `system_menu` 服务端下发 |
| 状态管理 | Pinia 已装但**未使用** | Pinia 完整使用 |
| 样式 | 手写 scoped CSS + CSS 变量 | UnoCSS + sass + 全局组件库 |
| 时间工具 | `utils/format.ts`（手写，兼容 epoch 毫秒/ISO） | `utils/formatTime.ts`（dayjs） |
| 构建 | `vue-tsc --noEmit && vite build` | 见 `package.json`（pnpm） |

## 五、已知问题与改进点

| 问题 | 现状 | 建议 |
|---|---|---|
| 用户端未使用 Pinia | 已安装注册但无任何 store，状态散在组件内 | 会员信息（`profile`/`token`）与热门标签等可抽成 store，避免各组件重复读 localStorage |
| 行业/省份硬编码 | `getAllIndustries()` 返回写死的 15 个行业；列表页省份下拉硬编码 30 项 | 应改为从后端字典或 `/notice/stats` 动态获取，否则后端新增行业前端看不到 |
| 热词标签是假数据 | `api/notice.ts` 的 `hotTags` 是本地常量，与真实数据无关 | 后端补一个热词统计接口后替换 |
| 管理端代理被注释 | 直连 `localhost:48080`，依赖跨域配置 | 恢复代理或显式配置 CORS 白名单 |
| `notice.contact_phone` 明文匿名可读 | 所有 `/admin-api/notice/**` 匿名接口都会返回联系人电话 | 竞品的做法是脱敏 + 付费可见；本项目应至少在返回前按会员等级脱敏（详见 [`02-竞品功能拆解.md`](../产品/02-竞品功能拆解.md) §四） |
| 无数据导出 | 用户端无导出入口；管理端仅框架自带的 Excel 导出 | 数据导出是竞品高频功能，列为二期 |
| 无响应式/移动端适配 | 用户端为桌面布局 | 移动端（H5/小程序/APP）规划在三期 |
