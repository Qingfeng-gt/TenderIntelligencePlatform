## 六、采集可达性实测

> 来源：2026-09 对目标站点的一次性可达性实测。**结论有时效性** —— 站点改版、加 WAF、换接口都会让结论失效，接入前务必重新实测（尤其贵州两站已出现过改版为 zcy 的情况）。

### 6.1 实测结论

| 站点 | 列表可采 | 详情可采 | 结论 |
|---|---|---|---|
| **中国政府采购网** `www.ccgp.gov.cn` | ✅ 静态 HTML `/cggg/dfgg/{gkzb,zbgg,gzgg,xjgg}/` | ✅ 全文在 `#noticeArea` | **主源，已接入**。政府公开数据、服务端渲染、字段齐全（项目编号/预算/采购人/代理/联系人/开标时间） |
| 政采云搜索 `search.ccgp.gov.cn` | ⛔ 返回「频繁访问」限流页 | —— | **不可用**：IP 级限流 |
| **贵州省招标投标公共服务平台** `ztb.guizhou.gov.cn` | ⛔ JSON 接口 `/api/trade/search` 返回 `totalNum=0`（2026-09-08 起，09-13 复测未恢复） | ✅ `/api/trade/GetDetail/{Id}` 可用 | **已接入但 2026-09-14 停用**（一轮采不到任何公告）；源码保留，源站恢复后改 `enabled` 即可 |
| 千里马招标网 `qianlima.com` | ✅ `/zbgg/`、`/p2` 分页 | ⛔ 华为云 WAF 419 验证 | 备源：仅列表可用，需浏览器渲染才能取详情 |
| 中国采购与招标网 `chinabidding` | ⚠️ 首页 200 | ⛔ 深链接 404 | 备源：需再研究详情页 URL 规律 |
| **全国公共资源交易平台** `ggzy.gov.cn` | ✅ 表单 POST `/information/pubTradingInfo/getTradList`（JSON） | ✅ `/information/deal/html/b/…` 服务端直出 | **已接入（2026-09-14）**。~~需 headless 浏览器~~ —— 该判断经 2026-09-14 实测推翻，详见 §6.2 |
| CEB 公共服务平台 `cebpubservice.com` | ⛔ 搜索界面带 Vaptcha 人机验证 | —— | **弃用** |
| 贵阳市公共资源交易中心 `ggzy.guiyang.gov.cn` | ⛔ 已改版为 zcy | —— | 需按新站结构重新评估 |

**规律**：服务端渲染（SSR）的地方政府站点可直接 HTTP 抓取；带人机验证、WAF 或 JS 二次渲染的站点需要 headless 浏览器（二期能力）。

#### 6.1.1 31 个省级政府采购网实测（2026-09-11）

> 目的：验证 §三 的「域名规律可批量配置化接入」推论。**结论：否定。** 逐站探测结果如下（首页可达性 + 列表页结构）。

**不可达（5 站，`.gov.cn` 域名解析或连接失败）**：北京、黑龙江、江西、广东、四川。

**可达但结构不可批量复用（各站列表页路径、详情页模板均不同）**：

| 省 | 实测现象 |
|---|---|
| 河北 | TRS 静态站，但列表页在 `/province/cggg/{zbgg,...}/index_N.html`（`.html` 非 `.htm`），详情页为**表单式模板**（`<td class='title'>` 表格），**无** `#noticeArea`、**无** `h2.tc` 之外的中央站锚点 |

### 6.2 各站点采集技术要点

**中国政府采购网（已实现）**
- 列表页按公告类型分目录：`/cggg/dfgg/{gkzb 公开招标, zbgg 中标, gzgg 更正, xjgg 询价}/`
- 翻页：第 N 页为 `{path}index_{N}.htm`
- 详情页字段分布在 HTML 中，用正则/标签文本锚点取值（锚点清单见 [`06-数据采集设计.md`](../技术/06-数据采集设计.md) §4.1）
- 附件为详情页正文里的链接（统一带 `ignore=1` 属性），解析出文件名/直链/类型/大小存入 `notice_attachment`；**文件本体不下载**，用户点链接到源站下载（解析规则见 [`06-数据采集设计.md`](../技术/06-数据采集设计.md) §4.4）

**全国公共资源交易平台（已实现，2026-09-14 接入）**

列表接口（**表单 POST**，非 GET）：
```
POST https://www.ggzy.gov.cn/information/pubTradingInfo/getTradList
Content-Type: application/x-www-form-urlencoded
X-Pass-Token: <留空>
Referer: https://www.ggzy.gov.cn/deal/dealList.html

DEAL_TIME=01&DEAL_CLASSIFY=01&PAGENUMBER=1
```
- `DEAL_TIME` **必填**：`01` 当天 / `02` 近三天 / `03` 近十天 / `04` 近一月 / `06` 自定义（配 `TIMEBEGIN`/`TIMEEND`，格式 `yyyy-MM-dd`，**日粒度**）。**缺失时接口返回 404 页面而非空列表**。
- `DEAL_CLASSIFY` **必填且不能为 `00`** —— 取 `00`「全部」返回 0 条，必须按类别分频道：`01` 工程建设 / `02` 政府采购 / `03` 土地使用权 / `04` 矿业权 / `05` 国有产权 / `21` 碳排放权 / `22` 排污权 / `23` 药品采购 / `24` 二类疫苗 / `25` 林权 / `90` 其他。
- 响应：`{"code":200,"data":{"records":[…20条…],"total":N,"pages":P}}`；错误码 `829` 需验证码、`800` 操作过于频繁、`804` 请细化查询条件、`801` 错误。

> ⚠️ **`total` 在 1000 条封顶，且是静默截断**。实测：`当天` 全部类别安全；`近三天` 政府采购即触顶；`近十天` 起 4 个类别触顶。故采集固定用 `DEAL_TIME=01`，靠 2 小时一调度重复覆盖当天来兜底。**把窗口放宽会静默丢数据。**

详情页：列表给的 `url` 是 `/information/deal/html/**a**/{地区码6位}/{类型4位}/{日期8位}/{hash}.html` —— 这是**外壳页**，正文在同路径的 `/html/**b**/…` 页（外壳内 `var firstLastUrl` 即该 b 页地址）。

> ⚠️ **正文缺失是常态**：该平台只做元数据汇聚，正文留在原交易平台。2026-09-14 每类抽 10 条实测正文可得率：**工程建设 7/10、政府采购 2/10、国有产权 0/10**。且无法在列表阶段预筛（类型码与有无正文无稳定对应）—— 必须抓详情才知道。正文为空的记录**跳过不入库**。

**贵州省招标投标公共服务平台（已实现，2026-09-14 停用）**
- 列表接口：`/api/trade/search?pubDate=&pubType=&region=&industry=&prjType=&noticeType=&noticeClassify=&pageIndex=&args=`
- 详情接口：`/api/trade/GetDetail/{Id}`
- 需 Cookie 预热 + `X-Requested-With: XMLHttpRequest`
- ⛔ 列表接口返回 `totalNum=0`（列表数据下线），一轮采不到任何公告，故 `crawler_site.enabled = b'0'`；源码与测试保留，源站恢复后一条 `UPDATE` 即可启用

### 6.3 字段统一映射规律

不同源站对同一概念的叫法不一致，采集时需归一。实测到的差异：

| 统一字段（本项目） | ccgp | ggzy.gov.cn（2026-09-14 实测锚点） | ztb.guizhou.gov.cn |
|---|---|---|---|
| 项目编号 | 项目编号 | 优先取源站结构化字段 `tenderProjectCode`；为空的落「招标项目编号 / 采购项目编号 / 项目编号 / 招标编号 / 交易编号」 | 招标编号 / 交易编号 / 统一交易码 |
| 预算金额 | 预算金额 | 预算金额 / 项目预算 / 采购预算 / 最高限价 / 招标控制价 | 项目预算（单位可能是元或万元） |
| 投标截止 | 投标截止时间 | 投标截止时间 / 投标文件递交截止时间（**源站常与开标时间合并写作「投标截止时间（开标时间）：…」，此时 deadline 与 openTime 同值**） | 投标截止时间 |
| 采购人 | 采购人名称 | 招标人 / 采购人 / 建设单位 / 采购单位 | 招标人 / 采购人 / 建设单位 |
| 代理机构 | 采购代理机构 | 招标代理机构 / 采购代理机构 / 代理机构 | 代理机构（缺失时用发布机构 `Source`） |
| 投标保证金 | 投标保证金 | 投标保证金 | 投标保证金 |

> 映射结果统一落到 `notice` 表字段，见 [`07-数据模型-现状.md`](07-数据模型-现状.md) §2.1。

> ⚠️ **省份必须存简称，不能存源站给的全称**：ggzy 的 `provinceText` 是「四川省」「广西壮族自治区」，而库内口径（`NoticeRegionExtractor` 的输出、前端省份下拉的 value、后端查询的精确相等匹配）都是**简称**「四川」「广西」。直接存全称会让这些记录**按省份筛不出来** —— 这个坑 ccgp 已踩过一次（见 `user-web/src/views/NoticeListPage.vue` 注释）。ggzy 适配器把全称原样喂回 `NoticeRegionExtractor` 做归一，`region_code` 则直取源站 6 位码。
