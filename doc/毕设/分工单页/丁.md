## 二、我具体怎么做

1. **第 1 周先做两件事，都不依赖丙**：
   - **定 200 条评测集的标注规范**（这是我最硬的资产，纯人力活，第 4 周是闸口）
   - **写 mock `NoticeApi` 实现**，先把查询理解和向量化跑起来——**不要等丙的真实现**（他第 1 周末才冻结签名，第 4 周才换真实现）
2. **建 `backend/sql/mysql/ai.sql`**：`notice_embedding`、`search_eval_query`，带 BaseDO 六件套。
3. **建包结构**：`understand/`（`QueryUnderstandService`）、`embedding/`（`EmbeddingService`）、`search/`（`VectorSearcher`、`Bm25Searcher`、`StructuredFilter`、`HybridSearchService`）、`rerank/`（`RerankService`）、`eval/`（`EvalService`）、`controller/{app,admin}/`、`dal/`、`enums/`。
4. **向量存储按队长拍板的方案落地**——不要自己搭集群：
   > 论文口径写的 `VECTOR(1024)` **在 MySQL 8 不存在**（MySQL 9 才有）。建议：向量存 `MEDIUMBLOB`/JSON，**应用层算余弦**。我的评测集才 200 条查询，全量暴力检索毫秒级——**把时间花在评测集和实验上**。
5. **LLM 相关（查询理解 / Embedding / Rerank）全走队长的 `tender-spring-boot-starter-ai`**——**不要自己写 HTTP 客户端**，而且它的**响应缓存**能让实验离网重跑。
6. **三路召回 + 融合**：向量（Embedding）+ BM25（关键词）+ 结构化过滤（地区/金额）。
   > ⚠️ **BM25 的边界已定**：丙拥有 ES 基础设施，**我只拥有融合 + Rerank + 评测**——BM25 就是 ES/Lucene 的默认相关性模型，不划清会撞车。
7. **Rerank 重排序**，然后跑 5 方法 × 3 指标对比。
8. **前端**：`AiSearchPage.vue` + 3 个组件（`AiSearchBox` / `IntentPanel` / `SearchResultCard`）；admin `views/ai-search/eval/index.vue`（对比表 + 散点图），菜单 id 段 **12830~12839**。
   > 放行 URL `/app-api/ai-search/**` 队长已加进 `permit-all-urls`。
9. **第 4 周前完成 200 条标注**，第 5 周把 mock 换成丙的真实现 + 接进 user-web。

## 八、我的实验设计

**指标**：Recall@10、MRR、NDCG@10
**对比方法**：① MySQL LIKE ② 纯向量检索 ③ 纯 BM25 ④ 本文混合检索 ⑤ 混合 + Rerank
**额外对比**：不同 Embedding 模型（bge-m3 vs text-embedding-3）
**预期**：混合 + Rerank 的 Recall@10 ≥ 0.85，比 LIKE 提升 50%+
