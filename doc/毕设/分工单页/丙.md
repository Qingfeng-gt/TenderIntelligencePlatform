## 三、我具体怎么做

### 第 1 周（我最重要的一周，三个人在等我）

1. **冻结 `notice` 表结构**。
2. **冻结 `NoticeApi` 签名，读 + 写两侧一起**：
   - **读**：查公告 + 标签筛选 + `NoticeRespDTO` → 给丁、戊
   - **写**：`upsert(NoticeDTO)` → 给**乙**（他的 `NoticeUpsertService` 现在直接 import 了我的 `NoticePortalDO` / `NoticePortalMapper`）
   - **只定签名不实现**——丁/戊/乙 先写 mock，第 4 周换我的真实现。冻结后**只加不改**。
3. **这件事本身就是我论文的创新点 1**（统一字段映射层），不是额外负担。

### 第 2 周起

4. **统一字段映射层**：把 ccgp / ggzy 的异构字段映射到 `notice`。
5. **Redis 热点公告缓存**，再上 **ES 全文检索**。
   > ⚠️ **边界已定**：ES 基础设施归我（建索引、灌数据、压测）；**丁只拥有融合 + Rerank + 评测**——因为 BM25 就是 ES/Lucene 的默认相关性模型，不划清两人会撞车。
6. **扩展 `/notice/list`**：加 `tagIds` / `budgetMax` / `region` 参数（戊要用 `tagIds` 做联动筛选）。
7. **在 `NoticeListPage.vue` 里留出挂载点**（搜索框 slot + 标签 chip slot）——**丁、戊 只能新增文件，改不了我的文件**，挂载点必须我留。
8. **收藏/订阅**（若做）：`notice_favorite` 表 + `/notice/favorite/toggle`。
   > 若吃不住工作量，**优先砍这一项**——§0 第 4 条已说明收藏功能现在不存在，砍掉不影响其他模块。
9. **admin 公告管理页** + 菜单 id 段 **12850~12859**。
10. **压测与优化**：JMeter 1000 并发、深分页优化、慢查询索引优化。
