## 三、我具体怎么做

1. **第 1 天先确认 `ScheduledCrawlTask` 开着**——30 天采集的时钟从第 1 周开始走，晚一周就少一周数据。现有代码已在每 2 小时自动跑，确认 `tender.crawler.schedule-enabled=true` 即可，**反爬改造可以推到第 2~3 周，不影响 30 天时钟**。
2. **建 `backend/sql/mysql/crawler.sql`**：`crawler_page_snapshot` 新表 + `crawler_task` 的 `ALTER TABLE` 加两列，都带 BaseDO 六件套。
3. **等丙第 1 周末冻结 `NoticeApi`**（**含写入侧 `upsert(NoticeDTO)`**）→ 把 `NoticeUpsertService.java:3-4` 里对 `NoticePortalDO` / `NoticePortalMapper` 的两个依赖换成它。**这是主文档 §6 第 6 项，改动成本很低**——`NoticeUpsertService` 本就是「所有 adapter 共用的持久化终点」，改的是一个类。
4. **反爬对抗**：在适配器实现层加 UA 轮换、请求间隔随机化、Cookie 池；JS 渲染站点接 Playwright 兜底。
5. **LLM 抽取兜底**（我的核心创新点）：规则抽取失败时，把 HTML 交给队长的 `tender-spring-boot-starter-ai` 抽字段——**不要自己写 HTTP 客户端**。结果写入 `crawler_page_snapshot` 的 `extract_mode` 字段，方便和规则路对比。
6. **SimHash 标题二次去重**（现在只有 `source_url` 唯一键）。
7. **抽取留痕**：每轮采集把页面快照 + 抽取结果写入 `crawler_page_snapshot`，供字段核对页展示与人工标注。
8. **前端**：改造 `views/crawler/index.vue`（统计卡 + 任务表 + 手动触发）；新增 `views/crawler/log/index.vue`（左列表右字段核对，可标注抽取错误）。菜单 id 段 **12820~12829**，`/crawler` 父菜单 12800 **已有，不要动**。

**适配器 SPI 的抽象目标**：把「列表页发现 → 详情页抓取 → 正文解析 → 附件下载 → 字段抽取」五步抽成模板方法，新站点只实现差异部分。
