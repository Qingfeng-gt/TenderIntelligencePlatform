## 二、我具体怎么做

1. **第 1 周先做两件事，都不依赖丙**：
   - **定四层标签本体**（行业 / 地区 / 金额 / 采购方式），含国标行业分类映射表
   - **写 mock `NoticeApi` 实现**，先把规则打标跑起来——**不要等丙的真实现**（他第 1 周末才冻结签名，第 4 周才换真实现）
2. **建 `backend/sql/mysql/tag.sql`**：3 张表，都带 BaseDO 六件套。
3. **建包结构**：`ontology/`（四层 × 四类 `INDUSTRY`/`REGION`/`BUDGET`/`PURCHASE_TYPE`）、`tagging/`（`RuleTaggingService` + `LlmTaggingService` + `AutoTaggingService`）、`graph/`（`CooccurrenceService` + `CommunityDetector`）、`recommend/`（`TagRecommendService`）、`controller/{app,admin}/`、`dal/`、`enums/`。
4. **规则打标**：金额、地区、采购方式——**从乙抽取的字段映射**。
   > ⚠️ **口径已定**：`notice.industry` 现在由乙的 `NoticeRegionExtractor`（关键词词典）推导写入，我的产出是**唯一权威标签源**，乙的 `industry` 降级为「规则抽取结果」，作为我 `RuleTaggingService` 的**输入之一**。
   > `NoticeRegionExtractor` 在**乙的私有区，我调不到**——**只能读 `notice.industry` 这个字段**。
5. **LLM 打标**：行业标签走队长的 `tender-spring-boot-starter-ai`（**不要自己写 HTTP 客户端**），**带置信度，低于阈值转人工**。结果写入 `notice_tag_rel` 的 `source`(LLM) + `confidence`。
6. **共现矩阵**：统计标签 co-occurrence，写入 `tag_cooccurrence`。
7. **Louvain 社区发现**，再基于共现矩阵做**标签推理推荐**（用户选「弱电智能化」→ 推荐常共现的「贵阳市 / 公开招标 / <50万」）。
8. **前端**：`TagExplorePage.vue` + `TagCloud.vue`（字号映射权重）+ `TagTopologyGraph.vue`（**echarts-graph 力导向图**）；admin `views/tag/manage/index.vue`（标签树 + 详情 + 共现 Top5），菜单 id 段 **12840~12849**。
   > 放行 URL `/app-api/tag/**` 队长已加进 `permit-all-urls`。
9. **联动筛选**：用丙的 `/notice/list?tagIds=1,2,3`；**要向丙要标签 chip 的挂载入口**（`NoticeListPage.vue` 的 slot 由丙留，我改不了他的文件）。
10. **第 4 周前跑通 500 条打标**，第 5 周接进 user-web。
