## 二、我具体怎么做

### M1 站点发现

1. **插槽已就绪，不用碰公共文件**：`tender-module-discovery` 空壳已注册进 `pom.xml`、菜单 id **12810** 已预置、`tender.discovery:` 配置段已留好。
2. **建 `backend/sql/mysql/discovery.sql`**：`discovery_task`（只留最终结果 + 关键步骤）、`discovery_candidate`（候选 + 是否招投标站 + 可访问性），两表都带 BaseDO 六件套。
3. **同一文件里写 `crawler_site` 的 `ALTER TABLE`**（加 `province`/`city`/`site_type`/`health_status`/`discovered_by`）→ **发群里让乙确认**，因为 `channels`/`config` 是他的解析入口。
4. **包结构**：`agent/DiscoveryAgent`（搜索 → 抓首页 → LLM 判站）、`agent/tool/{SearchTool,FetchTool,SiteJudgeTool}`、`service/`、`controller/admin/discovery/`、`dal/`、`enums/ErrorCodeConstants`、`framework/config/DiscoveryProperties`。
5. **LLM 判站走队长的 `tender-spring-boot-starter-ai`**（配置读 `tender.discovery:`）——**不要自己写 HTTP 客户端**，否则三份 key 管理、三份限流。
6. **写 `crawler_site` 时自己定义一个只做 insert/update 的 `DiscoveredSiteDO`**——**不要依赖乙的任何 Java 类**（同一张表两个 DO 是毕设场景的正确取舍）。
7. **前端** `views/discovery/{agent,candidates}/index.vue`——admin 是菜单驱动，**不用改路由**。

### M1 已降级，别按论文标准做

砍掉：ReAct 全流程留痕、`AdapterCodeGenerator` 适配器骨架生成、`SiteScoreCalculator` 四维评分模型（降为**可访问性 + 是否招投标站**两档）、20 关键词跑批实验。
工具从 4 个减到 **3 个**（Profile 合并进 Judge）。**第 5 周强制收口**，不再加需求。

### M6 移动端 App

1. **UniApp 骨架队长已搭好**（能装依赖、能编译、能起空白页）→ 直接写四页：`pages/notice/`（列表 + 筛选）、`pages/notice-detail/`、`pages/my-bids/`、`pages/login/`。
2. **接口零改造**：公告走 `/admin-api/notice/*`（已放行免登录），投标走 `/app-api/bid-project/*`（要求 token）。
3. **登录**：滑块验证码在 uni-app 里用不了，**队长已在插槽阶段关掉开关，我不碰 yaml**。
4. **三个对比 demo**：**先冻结功能清单与测试数据，再写三份实现**——功能不一致则基准数据没有可比性。
5. **跑基准**：固定测试机与系统版本；每指标**跑 3 轮取均值**并报告方差；记录构建产物哈希；跑基准前清后台进程。
