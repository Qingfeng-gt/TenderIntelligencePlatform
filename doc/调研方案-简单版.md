# 招投标平台调研方案（简单版）

> 就干三件事：看别人的页面、想数据库怎么建、找能爬的网站。

---

## 一、调研别人的页面

### 怎么做

1. 打开千里马招标网、剑鱼标讯这两个平台（注册免费账号）
2. 把所有能点的页面都点一遍，逐个截图
3. 每个页面记下来：**这个页面叫什么、上面展示了哪些内容、有哪些筛选条件、有什么按钮**

### 举个例子

比如打开**招标公告列表页**，你看到的是：

```
[搜索框：输入关键词]
[筛选：地区▼ 行业▼ 时间▼ 金额▼ 公告类型▼]
--------------------------------------------------
▶ 贵阳市市政工程维修项目招标公告    [公开招标] 贵州·贵阳  2026-09-05  预算:320万
▶ 遵义市医疗设备采购项目            [公开招标] 贵州·遵义  2026-09-05  预算:150万
▶ 毕节市学校食堂食材采购            [竞争性谈判] 贵州·毕节 2026-09-04  预算:80万
...
[上一页] 1 2 3 4 5 [下一页]
```

那你就记录：

> **页面名称**：招标公告列表页
> **展示内容**：每条公告显示 项目名称、公告类型标签、地区、发布日期、预算金额
> **筛选条件**：关键词搜索、地区、行业、时间、金额区间、公告类型
> **按钮**：点标题进详情、分页

再比如打开**招标详情页**，你看到：

```
项目名称：贵阳市市政工程维修项目
项目编号：GY2026-G001
预算金额：320万元
投标截止时间：2026-09-20 09:00
开标地点：贵阳市公共资源交易中心二楼
采购人：贵阳市城管局  联系人：张主任  电话：0851-xxxxxxx
代理机构：贵州XX招标公司  联系人：李工  电话：0851-xxxxxxx
投标保证金：3万元，账户：贵阳市公共资源交易中心，建行XX支行
公告正文：......（一大段文字）
附件：[招标文件.pdf] [图纸.zip]
```

那你就把这些字段全记下来，后面建数据库要用。

### 要调研的页面（不用全记，重点这几个）

| 页面 | 看什么 |
|---|---|
| 首页 | 搜索框在哪、推荐什么内容 |
| 招标列表页 | 列表显示哪些字段、有哪些筛选 |
| 招标详情页 | **重点**：把所有字段抄下来 |
| 中标列表/详情页 | 中标单位、中标金额、候选人排名 |
| 搜索结果页 | 高级搜索有哪些筛选条件 |
| 订阅页 | 订阅时能填哪些条件（关键词/地区/金额/推送方式） |
| 企业详情页 | 企业信息有哪些字段、历史中标怎么展示 |
| 收藏/个人中心 | 有哪些功能 |

## 二、推导数据库表

### 怎么做

1. 把第一步记录的所有字段列出来
2. 按"这是描述什么的"分组：描述项目的放一起、描述企业的放一起、描述用户操作的放一起
3. 每组就是一张表，给表起个名字，给每个字段定个类型

### 举个例子

从详情页抄下来的字段有：

```
项目名称、项目编号、预算金额、投标截止时间、开标地点、
采购人名称、采购人电话、代理机构名称、代理机构电话、
保证金金额、保证金账户、公告正文、附件文件名...
```

**第一步：分组**

- 描述"这个招标项目本身"的：项目名称、项目编号、预算金额、投标截止时间、开标地点、公告正文 → 这是**公告表**
- 描述"采购方和代理"的：采购人名称、采购人电话、代理机构名称、代理机构电话 → 这是**采购方表**（也可以放公告表里，但单独建表更规范，因为一个采购方会发很多标）
- 描述"保证金"的：保证金金额、保证金账户 → 字段少，放公告扩展表里就行
- 描述"附件"的：附件文件名 → 一个公告可能有多个附件，单独建**附件表**

**第二步：建表**

公告表（tender_notice）：

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| project_name | varchar(500) | 项目名称 |
| project_code | varchar(64) | 项目编号 |
| budget | decimal(15,2) | 预算金额（元） |
| bid_deadline | datetime | 投标截止时间 |
| open_location | varchar(500) | 开标地点 |
| content | longtext | 公告正文 |
| publish_time | datetime | 发布时间 |
| source_url | varchar(500) | 原文链接 |

附件表（tender_attachment）：

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| notice_id | bigint | 属于哪个公告（关联公告表id） |
| file_name | varchar(255) | 文件名 |
| file_type | varchar(16) | pdf/word/zip |
| file_url | varchar(500) | 下载地址 |

**第三步：判断关系**

- 一个公告 → 多个附件（1对多）
- 一个采购方 → 多个公告（1对多）
- 一个用户 → 多个收藏（1对多）

画个简单的关系图：

```
采购方表 ──1对多──> 公告表 ──1对多──> 附件表
                       │
                       └──1对多──> 中标结果表
用户表 ──1对多──> 收藏表 <──多对1── 公告表
用户表 ──1对多──> 订阅规则表
```

### 大概要建多少张表

不用精确，大概 **12~15 张**就够了：

| 模块 | 表 | 几张 |
|---|---|---|
| 标讯 | 公告表、公告扩展表、附件表、变更关联表 | 4 |
| 中标 | 中标结果表、中标候选人表 | 2 |
| 企业/采购方 | 企业表、企业资质表、采购方表 | 3 |
| 用户 | 订阅规则表、收藏表、企业监控表 | 3 |
| 采集 | 站点配置表、采集日志表 | 2 |
| **合计** | | **14** |

> 记住一个原则：**页面上有什么内容，表里就有什么字段**。页面上看不到的东西，不要凭空建表。

## 三、找能爬的网站

### 怎么做

1. 列出所有公开招投标网站（官方的优先，商业平台的不用爬，人家有反爬）
2. 每个网站打开看看：能不能访问、列表页好不好抓、详情页字段全不全
3. 分个级：马上能用的（P0）、以后再说的（P1）、先不管的（P2）

### 举个例子

比如调研**中国政府采购网**（ccgp.gov.cn）：

1. 打开首页，能正常访问，不需要登录
2. 点进招标公告列表，翻页时 URL 变成 `.../index_2.htm`，说明是静态页面，好爬
3. 点进详情页，字段很全：项目编号、预算、截止时间、采购人、代理机构、保证金、附件，都有
4. 看 robots.txt，没有禁止采集
5. 结论：**P0，第一个接入**

再比如调研**某省公共资源交易中心**：

1. 打开首页，能访问
2. 列表页翻页时，F12 看到是 AJAX 请求，返回 JSON 数据 → 更好，直接调接口就行
3. 详情页字段也全
4. 结论：**P0**

再比如**国家电网采购平台**：

1. 打开首页，要看公告必须登录
2. 注册需要企业资质，个人注册不了
3. 结论：**P1/P2，暂时不接，等以后有企业资质再说**

### 重点关注的网站（不用全爬，先搞这几个）

**P0（先跑通这 2~3 个）：**

| 网站 | URL | 为什么先搞 |
|---|---|---|
| 中国政府采购网 | ccgp.gov.cn | 全国数据、结构稳定、不需要登录 |
| 贵州省公共资源交易云 | ggzy.guizhou.gov.cn | 本地数据、用户在贵州 |
| 贵州省招标投标公共服务平台 | ztb.guizhou.gov.cn | 结构简单、好爬 |

**P1（第二批，全国各省政府采购网）：**

域名规律都是 `www.ccgp-省份拼音.gov.cn`，比如：
- 四川：ccgp-sichuan.gov.cn
- 云南：ccgp-yunnan.gov.cn
- 广东：ccgp-guangdong.gov.cn
- ...（全国 30 多个省，结构都差不多，写一个模板批量适配）

**P2（以后再说）：**
- 各省公共资源交易中心（域名不统一，要逐个适配）
- 国企采购平台（大多要登录，反爬强）
- 行业垂直网站（数据量小）

### 每个网站记录什么

就记这几条，不用搞复杂的评分表：

```
网站名称：中国政府采购网
URL：ccgp.gov.cn
能不能直接访问：能 / 不能（需要登录）
列表页好不好抓：好（静态HTML）/ 一般（AJAX）/ 难（需要渲染）
详情页字段全不全：全（30+字段）/ 一般（10~20个）/ 少（<10个）
有没有附件下载：有 / 没有
robots允不允许爬：允许 / 禁止
优先级：P0 / P1 / P2
```

## 四、最后产出什么

调研完了，交 3 个东西就行：

1. **页面截图 + 字段记录**（一个 Word 或 Markdown，把每个页面的截图和字段贴进去）
2. **数据库表设计**（一个 Markdown，每张表列字段名/类型/说明，画个关系图）
3. **可爬网站清单**（一个 Excel，每行一个网站，记 URL、能不能爬、优先级）

就这些，不用写长篇大论的报告。
