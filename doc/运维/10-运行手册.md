# 运行手册

> 编制：2026-09-10
> 适用范围：本地/开发环境完整跑通「采集 → 入库 → 用户端检索 → 发起投标」全链路。
> 环境基线：WSL(Ubuntu) 内跑 MySQL + Java 17 + Maven；Windows 上跑 Node（两个前端）。

---

## 〇、环境要求

| 组件 | 版本 | 位置 | 备注 |
|---|---|---|---|
| JDK | 17 | WSL | 当前实测 `openjdk 17.0.20.1` |
| Maven | 3.9.x | WSL | —— |
| MySQL | 8.x | WSL | 库名 `tender`，字符集 `utf8mb4` |
| Redis | 任意 | WSL | `local` profile 连 `127.0.0.1:6379` db 0 |

## 一、数据库初始化（一次性）

```bash
# WSL 内执行
cd /mnt/d/MyProjects/TenderIntelligencePlatform/backend/sql/mysql

# 1) 建库（脚本本身不建库）
mysql -uroot -p123456 -e "CREATE DATABASE tender DEFAULT CHARACTER SET utf8mb4"

# 2) 框架基础 29 张表（infra_/system_/member_user）+ 最小种子
mysql -uroot -p123456 tender < tender.sql

# 3) 业务全量 5 张表 + 菜单/站点种子（必须在 tender.sql 之后）
mysql -uroot -p123456 tender < notice.sql

# 4) 仅启用 Quartz 的环境（dev/test）需要；local 不需要
mysql -uroot -p123456 tender < quartz.sql
```

> ⚠️ 三个脚本都是 **DROP + CREATE 全量重建**，重复执行会清空已有数据。各文件详解见 [`11-SQL脚本说明.md`](11-SQL脚本说明.md)。

初始化后的内置数据：

| 数据 | 说明 |
|---|---|
| 后台账号 | `admin`（超级管理员，权限旁路，不依赖 `role_menu`） |
| 演示会员 | `demo123` / `123456`（`member_user.id = 1`，与演示投标数据 `user_id = 1` 对应） |
| 演示标讯 | 20 条（`notice.id` 1-20，四类齐全） |
| 采集站点 | 3 行：`ccgp` 中国政府采购网、`ggzy` 全国公共资源交易平台（均启用）、`ztb_gz` 贵州省招标投标公共服务平台（**2026-09-14 已停用**，`enabled=b'0'`，源码与配置保留） |

## 二、启动后端

```bash
cd /mnt/d/MyProjects/TenderIntelligencePlatform/backend

# 首次 / 改动代码后：全链安装
# （新增模块 crawler/bid 必须先 install，否则 server 打包时解析不到依赖）
mvn -DskipTests install

# 只重打包 server
mvn -pl tender-server -am -DskipTests package

# 启动（local profile，端口 48080）
java -jar tender-server/target/tender-server.jar --spring.profiles.active=local
```

**验证服务已起**：

```bash
curl "http://127.0.0.1:48080/admin-api/notice/stats"
# 期望返回 {"code":0,"data":{"todayCount":...,"totalCount":...,"provinces":...,"industries":...}}
```

> **WSL drvfs 跨盘文件系统的两个坑**（已在实践中反复踩到）：
> 1. **Maven 增量编译判定偶发失效** —— 改了源码但没重新编译。改代码后一律用 `mvn -DskipTests install` 全链重装，不要迷信增量。
> 2. **jar 被文件锁** —— 服务运行中 `package` 会报 `tender-server.jar.original` 相关错误。先停服务：`fuser -k 48080/tcp`，再打包。

**Profile 差异**（详见 [`03-系统架构.md`](../技术/03-系统架构.md) §六）：

| 项 | `local`（默认） | `dev` |
|---|---|---|
| 端口 | 48080 | 48080 |
| Redis | `127.0.0.1:6379` db 0 | 远程地址 db 1 |
| Quartz | **排除**（`spring.autoconfigure.exclude`） | 启用（jdbc job-store，集群）※ 二者均为脚手架基线默认值，非本项目选择；采集定时走 `@Scheduled`，不受此项影响，详见 [`03-系统架构.md`](../技术/03-系统架构.md) §六 |
| 验证码 | `tender.captcha.enable: false` | 默认 true |
| mock 登录 | `tender.security.mock-enable: true` | 默认 false |

> ⚠️ `local` 环境的 `mock-enable: true` 允许用特定前缀的假令牌直接登录，**只能用于本机开发**。生产环境必须确保为 `false`。

## 三、启动前端

### 3.1 user-web（用户门户，端口 3001）

```bash
cd user-web
npm install        # 首次
npm run dev        # http://localhost:3001
```

Vite 已配置代理，`/admin-api` 与 `/app-api` 都会转发到 `http://127.0.0.1:48080`，无需额外配置。

### 3.2 admin-web（管理后台，端口 80）

```bash
cd admin-web
pnpm install       # 首次（仅支持 pnpm）
pnpm dev           # http://localhost:80
```

> ⚠️ `admin-web/vite.config.ts` 中的 **proxy 被注释掉了**，请求直连 `http://localhost:48080/admin-api`。因此后端必须开在 `localhost:48080`，且需允许来自 `localhost:80` 的跨域请求。
>
> 端口 80 在部分环境需要管理员权限；如需改动，修改 `admin-web/.env` 的 `VITE_PORT`。

## 四、触发采集

采集有**手动**与**定时**两种触发方式。

### 4.1 手动触发

```bash
# 1) 采集所有已启用站点（当前为 ccgp + ggzy；ztb_gz 已停用，会被跳过）
curl -X POST "http://127.0.0.1:48080/admin-api/crawler/run"

# 2) 只采指定站点
curl -X POST "http://127.0.0.1:48080/admin-api/crawler/run?siteCode=ccgp"

# 3) 查询某站点最近一次任务
curl "http://127.0.0.1:48080/admin-api/crawler/task/latest?siteCode=ccgp"

# 4) 分页查询任务日志
curl "http://127.0.0.1:48080/admin-api/crawler/task/page?pageNo=1&pageSize=10"

# 5) 站点配置列表
curl "http://127.0.0.1:48080/admin-api/crawler/site/list"
```

接口**立即返回任务号**，采集在后台异步执行。~~单站点 4 个频道各 1 页约 80~100 条公告，约 3~5 分钟~~（**2026-09-14 更正**：已按站点分别估算 —— `ccgp` 22 个频道 41 页 = 820 条候选，按 3s 限速约 **41 分钟**；`ggzy` 10 个频道最多 16 页 ≈ 320 条候选，约 **16 分钟**，且会按源站返回的 `pages` 提前收手，实际更短）。

> ⚠️ 采集任务在**单线程**线程池（`crawler-run`）中串行执行。手动触发后若立刻再次触发，同站点会被防重入守卫跳过。

### 4.2 管理端触发（推荐日常使用）

打开 `http://localhost:80` → 登录 `admin` → 左侧菜单「**数据采集中心**」`/crawler`：

- 站点卡片显示每个站点的启用状态、频道数、最近任务状态与新增/更新条数；
- 「立即采集」按站点触发，「采集全部」触发所有启用站点；
- 页面**每 5 秒自动轮询**最近任务状态，可以实时看到计数器滚动；
- 下方任务日志表可按站点筛选、分页查看历史任务。

### 4.3 定时触发

定时采集由 `ScheduledCrawlTask` 驱动，默认**每 2 小时**一次：

```yaml
tender:
  crawler:
    schedule-enabled: true          # 总开关，false 则完全不跑定时
    schedule-cron: "0 0 */2 * * ?"  # Spring 6 段 cron
```

改完配置需重启服务。

> ⚠️ **这不是 Quartz 任务** —— 它是 Spring 原生 `@Scheduled`，因此**不会出现在管理端「定时任务」页面**（`infra_job` 表里没有它），管理端无法启停或修改 cron，只能用配置文件。这一点与框架自带的 4 个日志清理 Job 不同。
>
> 由此推出一条运维结论：**定时采集在 `local` 与 `dev` 两种 profile 下都会跑**，与 Quartz 开关无关（`local` 排除了 Quartz 自动配置，采集照跑）。所以将来若新增 `prod` profile 并排除 Quartz，**采集定时依然有效** —— 前提是 `schedule-enabled` 为 `true`。Quartz 开关只决定 `infra_job` 里的任务（`tokenCleanJob`、三个日志清理 Job）是否真的执行。

### 4.4 采集结果验证

```bash
# 今天新增了几条
curl "http://127.0.0.1:48080/admin-api/notice/stats"

# 看最新采到的真实数据（来源为「中国政府采购网」或「全国公共资源交易平台」）
curl "http://127.0.0.1:48080/admin-api/notice/list?pageNo=1&pageSize=5"
```

## 五、端到端演示路径

1. **首页**（`http://localhost:3001`）—— 统计条显示今日新增/总标讯/覆盖省份/行业数，列表含**采集到的真实数据**（来源标注「中国政府采购网」或「全国公共资源交易平台」）。
2. **搜索** —— 在搜索框输入关键词回车，或点导航「招标公告」进入 `/notice?type=tender`；可用省份、行业、时间范围进一步筛选。
3. **详情页** —— 点击任一招标公告，可见**采集实测提取的字段**：项目编号、预算金额（万元）、投标截止时间、开标时间、招标人、代理机构、联系人。
4. **发起投标** —— 招标类（`type === 'tender'`）详情页右上角有「发起投标」按钮；未登录会跳转到登录页并带回跳地址。
5. **登录** —— 用演示会员 `demo123` / `123456` 登录（`local` 环境已关闭验证码；若开启需完成滑块拼图）。
6. **填写投标** —— 弹窗填写拟投标金额（万元）、投标文件名 → 确认递交。
7. **我的投标** —— 进入 `/my-bids`，看到刚创建的记录，状态为「已递交」。
8. **状态流转** —— 点「标记开标」→「待开标」→ 可「确认中标」/「确认未中标」/「放弃项目」。**终态不可再变更**，非法迁移会被后端状态机拒绝。

> 平台定位是**投标管理工具**：真实递交到公共资源交易平台需 CA 数字证书，属线下动作，本系统以状态机模拟流程。

## 六、常见操作

### 6.1 抓更多历史公告

编辑 `crawler_site` 表中对应站点的 `channels` JSON，把目标频道的 `pageCount` 调大：

```json
[{"path":"/cggg/dfgg/gkzb/","name":"地方-公开招标公告","type":"tender","pageCount":3}]
```

CCGP 的翻页规则是第 N 页为 `{path}index_{N}.htm`，因此 `pageCount: 3` 会抓前 3 页。改完无需重启，下次触发采集即生效。

> ⚠️ **调大 `pageCount` 前先看单轮耗时**：候选详情 URL 每轮**全量重抓**（不是只抓新增），耗时 ≈ `总页数 × 20 × interval_ms`。当前 `ccgp` 22 个频道合计 41 页 = 820 条候选，按 3s 限速约 **41 分钟**。若继续调大，需同时确认仍落在 2 小时的采集间隔内，否则下一轮会被站点级 RUNNING 守卫跳过。各频道当前分档与实测产量见 [`06-数据采集设计.md`](../技术/06-数据采集设计.md) §3.2。
>
> 另：`channels` 列已由 `varchar(1024)` 加宽至 `varchar(4096)`（当前 22 频道 JSON 约 1900 字符），手工拼 JSON 时注意别超列长。

> ⚠️ **`notice.sql` 是全量初始化脚本，改它不会改变已有库。** 该脚本的模式是 `DROP + CREATE + INSERT`（见文件头），只用于从零建库。**改 `notice.sql` 里的配置或种子数据 ≠ 改到运行中的库** —— 必须另跑等价的 `UPDATE`/`ALTER`。2026-09-11 就因此踩过一次：频道配置在文件里加了 `template` 字段，但库里没有，导致 `zygg` 频道被按地方模板解析，60 条中央公告的结构化字段全空。

### 6.1.1 部署新代码

服务以 `java -jar tender-server/target/tender-server.jar --spring.profiles.active=local` 方式运行（工作目录 `backend/`）。改动 Java 代码后：

```bash
# 1) 必须先停服务 —— 运行中的进程会锁住 jar，repackage 会报
#    "Unable to rename ... tender-server.jar to ... .jar.original"
# 2) 打包（-am 连带重建依赖模块；嵌套模块 jar 在 BOOT-INF/lib 下）
cd backend && mvn -o -pl tender-server -am package -DskipTests
# 3) 按原命令重启
java -jar tender-server/target/tender-server.jar --spring.profiles.active=local
```

> 停服务会把当时正在跑的采集任务留在 `RUNNING` 状态，**站点级防重入守卫会挡住后续触发**（直到 4 小时超时回收）。重跑前先手工收尾：
> ```sql
> UPDATE crawler_task SET status='FAILED', end_time=NOW(), error_msg='服务重启导致中断' WHERE status='RUNNING';
> ```
> 定时采集 cron 为 `0 0 */2 * * ?`（偶数整点），重启时留意是否正好跨越该时刻。

### 6.2 临时停用 / 重新启用某个源站

```sql
-- 停用（示例：ggzy）
UPDATE crawler_site SET enabled = b'0' WHERE code = 'ggzy';
-- 重新启用
UPDATE crawler_site SET enabled = b'1' WHERE code = 'ggzy';
```

`enabled = 0` 后，不带 `siteCode` 的「采集全部」会跳过它；带 `siteCode` 的定向触发会返回错误码 `CRAWLER_SITE_DISABLED`。停用**不改代码**：适配器与解析器保留，只是不再被调度。

> 现成用例：`ztb_gz` 已于 2026-09-14 按此方式停用（源站列表接口返回 0 条，一轮采集产不出公告）。**它的源码一行未删**，源站恢复后跑上面的「重新启用」即可：
> ```sql
> UPDATE crawler_site SET enabled = b'1' WHERE code = 'ztb_gz';
> ```

### 6.3 手动指定站点采集

`POST /admin-api/crawler/run?siteCode=ccgp` —— 定向采集，绕过 `enabled` 之外的站点筛选。

### 6.4 重置被卡住的采集任务

正常情况下，超过 **4 小时**仍为 `RUNNING` 的任务会在下次触发采集时被自动回收为 `FAILED`（`error_msg` 为「超时自动回收」）。若需立即处理：

```sql
UPDATE crawler_task SET status='FAILED', error_msg='手动清理',
       end_time=NOW() WHERE status='RUNNING';
```

### 6.5 查看日志

```bash
tail -f ~/logs/tender-server.log     # 后端日志（路径由 application.yaml 指定）
```

## 七、排障速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 前端首页一直转圈/时间显示异常 | 时间字段是 epoch 毫秒，未走 `utils/format.ts` 转换 | 检查是否直接渲染了原始时间字段，见 [`05-前端页面与接口调用.md`](../技术/05-前端页面与接口调用.md) §2.7 |
| 用户端登录后调接口 403 | **会员令牌打到了 `/admin-api`** | 会员接口必须走 `/app-api`（`api/app-request.ts`）。后端的 `TokenAuthenticationFilter` 会比对令牌类型与前缀 |
| 采集触发了但没有新数据 | ① 源站列表结构变化；② ~~`ztb_gz` 源站列表接口返回 0 条~~（**2026-09-14 已处置**：该站已停用 `enabled=b'0'`，不再参与「采集全部」；若定向触发它会返回 `CRAWLER_SITE_DISABLED`）；③ 内容与库中已有记录完全相同（去重跳过）；④ `ggzy`「当天」窗口下工程建设等类别产量为 0（实测常态，非故障） | 查 `/crawler/task/latest` 的 `listParsed` / `detailFailed` / `newInsert` 计数定位 |
| `ggzy` 抓到候选但没入库 | **正文为空被跳过** —— 该站只汇聚元数据，正文留在原平台（2026-09-14 每类抽 10 条实测有正文比例：工程建设 7/10、政府采购 2/10、国有产权 0/10）。适配器对空正文记录跳过不入库并计入 `detailFailed` | 正常现象。看任务详情里的「无正文跳过」日志；`detailFailed` 高而 `newInsert` 低是预期，不代表适配器坏 |
| 采集任务一直 RUNNING | 进程被杀导致任务未回填 | 等 4 小时自动回收，或按 §6.4 手动清 |
| `package` 报 `tender-server.jar.original` 错误 | jar 正被运行中的进程占用 | `fuser -k 48080/tcp` 停服务后再打包 |
| 改了代码但行为没变 | WSL drvfs 下 Maven 增量编译判定失效 | `mvn -DskipTests install` 全链重装 |
| 调度任务抛 NPE | 调度线程无租户上下文 | 定时任务类必须加 `@TenantIgnore`（现有 `ScheduledCrawlTask` 已加） |
| 管理端菜单不显示新页面 | 管理端路由由 `system_menu` 表下发 | 往 `system_menu` 插一行，见 [`03-系统架构.md`](../技术/03-系统架构.md) §七 |
| IDEA 编译后 Maven 编译失败 | IDEA 会在 `target/classes` 写 Error 占位类，伪装成 MapStruct 报错 | 清理 `target/` 后重新 `mvn install`，或确保 IDE 与 Maven 用同一输出目录 |

| 项 | 要求 |
|---|---|
| 演示账号 | 删除或改密：`demo123` / `123456`、后台 `admin` 默认口令 |
| mock 登录 | `tender.security.mock-enable` 必须为 `false` |
